## กฎเหล็ก

1. **แก้เฉพาะสิ่งที่ระบุไว้ใน Prompt นี้เท่านั้น**

   * ห้ามแก้ไข ลบ ย้าย หรือปรับปรุงโค้ดส่วนอื่นที่ไม่เกี่ยวข้องกับข้อกำหนดนี้
   * ห้ามปรับปรุงโค้ดเพิ่มเติมด้วยเหตุผลว่าเห็นว่าเหมาะสมกว่า
   * ห้าม refactor
   * ห้ามเปลี่ยนโครงสร้างระบบที่มีอยู่เดิมโดยไม่จำเป็นต่อการแก้ไขที่ร้องขอ

2. **ห้ามแตะต้องระบบ Accessibility เดิมโดยเด็ดขาด**

   * `aria-live` ทุกจุดต้องคงเดิม
   * ระบบ `sr-polite` และ `sr-assertive` ต้องคงเดิม
   * วิธีการประกาศข้อความด้วย Screen Reader ต้องคงเดิม
   * ห้ามเปลี่ยนลำดับการประกาศ
   * ห้ามลด เพิ่ม หรือเปลี่ยนข้อความประกาศเดิม
   * ห้ามเปลี่ยน `aria-label`, `role`, หรือ accessibility behavior ใด ๆ ที่ไม่เกี่ยวข้องโดยตรงกับข้อกำหนดนี้

3. **ข้อความและคำศัพท์เดิมทั้งหมดต้องคงไว้**

   * ห้ามแก้ไขข้อความภาษาไทยเดิม
   * ห้ามเปลี่ยนคำเรียกตัวละคร ผู้เล่น บอท ช่อง เหตุการณ์ ไอเทม หรือสถานะใด ๆ
   * ห้ามเปลี่ยนรูปแบบข้อความที่ระบบใช้ประกาศผ่าน Screen Reader
   * หากต้องเพิ่มข้อความเฉพาะกรณี “ของหมดแล้ว” ให้ใช้ข้อความและรูปแบบตามระบบเดิมของไฟล์ โดยห้ามปรับข้อความส่วนอื่น

4. **ห้ามแตะต้องระบบเกมอื่น**

   * ห้ามเปลี่ยนระบบทอยลูกเต๋า
   * ห้ามเปลี่ยนระบบเดิน
   * ห้ามเปลี่ยนระบบ Event Chain
   * ห้ามเปลี่ยนจำนวนเหตุการณ์สูงสุดต่อการทอย
   * ห้ามเปลี่ยนระบบผู้เล่นจริง
   * ห้ามเปลี่ยนระบบบอท
   * ห้ามเปลี่ยน Firebase
   * ห้ามเปลี่ยน Multiplayer
   * ห้ามเปลี่ยน Turn System
   * ห้ามเปลี่ยน Timer
   * ห้ามเปลี่ยนเสียง
   * ห้ามเปลี่ยน Animation
   * ห้ามเปลี่ยน UI logic
   * ห้ามเปลี่ยนกฎเกมส่วนอื่นทั้งหมด

5. **ห้ามสร้างระบบใหม่เกินกว่าที่จำเป็น**

   * ใช้โครงสร้างและตัวแปรของไฟล์เดิมให้มากที่สุด
   * เปลี่ยนเฉพาะ logic ที่จำเป็นสำหรับ `charges` และ `door` ตามข้อกำหนดด้านล่าง

6. **ต้องรักษาพฤติกรรมเดิมทั้งหมดที่ไม่ได้ระบุให้เปลี่ยน**

   * ทุกฟังก์ชันที่ไม่เกี่ยวข้องต้องทำงานเหมือนเดิม 100%
   * ห้ามทำให้ behavior เดิมส่วนอื่นเปลี่ยนไปแม้แต่น้อย

7. **ต้องส่งไฟล์กลับมาแบบเต็มไฟล์**

   * ต้องครบตั้งแต่บรรทัดแรกจนถึงบรรทัดสุดท้าย
   * ห้ามตัดทอน
   * ห้ามใช้ `...`

# สิ่งที่ต้องแก้ไขใน adventure80.js

## 1. ฟังก์ชัน `generateBoardConfiguration`

### 1.1 ช่อง `treasure`

เปลี่ยนระบบเดิมของช่อง `treasure` จากการใช้สถานะ `opened: true/false` ให้เป็นระบบนับจำนวนชิ้นด้วย `charges`

ค่าเริ่มต้นต้องเป็น:

`charges: 2`

หมายความว่า **ช่อง treasure แต่ละช่องมีไอเทมให้เก็บได้ทั้งหมด 2 ครั้ง**

เมื่อมีผู้เล่นตกช่องนี้:

* ถ้า `charges > 0` สามารถรับไอเทมได้
* เมื่อรับไอเทม ให้ลด `charges` ลง 1
* เมื่อ `charges` เหลือ `0` ช่องนั้นจะไม่มีไอเทมเหลือให้รับอีก

ต้องเป็นสถานะของช่องนั้นเอง ไม่ใช่จำนวนรวมทั้งกระดาน

### 1.2 ช่อง `key`

เปลี่ยนระบบเดิมของช่อง `key` จากการใช้สถานะ `opened: true/false` ให้เป็นระบบนับจำนวนชิ้นด้วย `charges`

ค่าเริ่มต้นต้องเป็น:

`charges: 2`

หมายความว่า **ช่อง key แต่ละช่องมีไอเทมให้เก็บได้ทั้งหมด 2 ครั้ง**

เมื่อมีผู้เล่นตกช่องนี้:

* ถ้า `charges > 0` สามารถรับไอเทมได้
* เมื่อรับไอเทม ให้ลด `charges` ลง 1
* เมื่อ `charges` เหลือ `0` ช่องนั้นจะไม่มีไอเทมเหลือให้รับอีก

ต้องเป็นสถานะของช่องนั้นเอง ไม่ใช่จำนวนรวมทั้งกระดาน

### 1.3 ช่อง `door`

เปลี่ยนระบบระยะทางของ `door` จากการกำหนดระยะทางแบบ Fix เดิม ให้เป็น **ระยะทางเดินหน้าแบบสุ่ม 5 ถึง 18 ช่อง**

ต้องใช้ขอบเขต:

* ต่ำสุด `5`
* สูงสุด `18`

และต้องมีข้อบังคับว่า หากคำนวณปลายทางแล้วเกินช่อง `79` ให้ส่งไปที่ช่อง `79` เท่านั้น

หลักการคือ:

`Math.min(79, currentPosition + distance)`

โดย `distance` ต้องอยู่ในช่วง `5–18` ตามข้อกำหนดนี้

ห้ามเปลี่ยนกฎส่วนอื่นของ `door`

# 2. ฟังก์ชัน `executeTurnAsync`

## 2.1 เมื่อผู้เล่นตกช่อง `treasure`

ให้ตรวจสอบค่า `charges` ของช่องนั้น

* ถ้า `charges > 0`

  * ลด `charges` ลง 1
  * แจกไอเทมของ treasure ให้ผู้เล่นตามระบบเดิม
  * ใช้ข้อความประกาศเดิมของเกม
* ถ้า `charges === 0`

  * ไม่แจกไอเทม
  * แสดง/ประกาศข้อความว่าของหมดแล้วตามระบบเดิม

**ห้ามเปลี่ยนข้อความประกาศเดิมหรือระบบ ARIA Live ที่ใช้อยู่**

## 2.2 เมื่อผู้เล่นตกช่อง `key`

ให้ตรวจสอบค่า `charges` ของช่องนั้น

* ถ้า `charges > 0`

  * ลด `charges` ลง 1
  * แจกไอเทมกุญแจให้ผู้เล่นตามระบบเดิม
  * ใช้ข้อความประกาศเดิมของเกม
* ถ้า `charges === 0`

  * ไม่แจกไอเทม
  * แสดง/ประกาศข้อความว่าของหมดแล้วตามระบบเดิม

**ห้ามเปลี่ยนข้อความประกาศเดิมหรือระบบ ARIA Live ที่ใช้อยู่**

## 2.3 เมื่อผู้เล่นตกช่อง `door` และเลือกใช้กุญแจ

ให้ผู้เล่นเดินหน้าไปตามระยะทางสุ่มของประตูนั้น โดยระยะทางต้องอยู่ในขอบเขต:

**5 ถึง 18 ช่อง**

และต้องจำกัดปลายทางไม่ให้เกินช่อง `79`

หลักการ:

`Math.min(79, currentPosition + distance)`

ต้องคงระบบการเลือกใช้กุญแจเดิมของเกมไว้

ต้องคงข้อความประกาศเดิมทั้งหมดไว้

ต้องคงระบบ ARIA Live เดิมไว้ทั้งหมด
