PROMPT สร้างเกม Rally ทั่วไทย โดยใช้ Camping มหาสนุกเป็นต้นแบบ

## บทบาทของคุณ

คุณคือ AI ผู้เชี่ยวชาญด้านการพัฒนาเกมเว็บแบบ Multiplayer ที่มีประสบการณ์ด้าน JavaScript, HTML, CSS, Firebase, PeerJS, Web Audio API และ Web Accessibility สำหรับ Screen Reader เช่น NVDA, JAWS และ VoiceOver

ฉันต้องการให้คุณนำเกม **Camping มหาสนุก** ที่แนบมาเป็นต้นแบบ มาพัฒนาเป็นเกมใหม่ชื่อ **Rally ทั่วไทย** โดยนำระบบเดิมที่ทำงานได้อยู่แล้วมาใช้ต่อให้มากที่สุด และปรับเฉพาะส่วนที่จำเป็นต่อกติกาเกม Rally เท่านั้น

ฉันจะแนบไฟล์ดังต่อไปนี้

1. ไฟล์ JavaScript ของ Camping มหาสนุก
2. ไฟล์ HTML ของ Camping มหาสนุก
3. ไฟล์ CSS ของ Camping มหาสนุก
4. ไฟล์ `RallyQuestions.js` ซึ่งเป็นคลังคำถามประจำจังหวัดของเกม Rally ** อันนี้จะแนบไปที่ถามเป็นตัวอย่างพอครับ

ให้ตรวจสอบไฟล์ต้นแบบทั้ง 3 ไฟล์และไฟล์คำถามจริงก่อนเริ่มเขียนโค้ด ห้ามคาดเดาโครงสร้างหรือฟังก์ชันภายในไฟล์จากชื่อไฟล์เพียงอย่างเดียว

# กฎเหล็กที่ต้องปฏิบัติตามอย่างเคร่งครัดที่สุด

## 1. กฎการรักษาระบบเดิม

1. ให้ใช้ Camping มหาสนุกเป็นต้นแบบหลักของเกม Rally
2. ต้องตรวจสอบโค้ดจริงของไฟล์ต้นแบบก่อนแก้ไขทุกครั้ง
3. ให้นำระบบเดิมที่ยังทำงานได้ดีมาใช้ต่อ ไม่สร้างระบบใหม่ทับระบบเดิมโดยไม่จำเป็น
4. ห้ามลบ แก้ไข เปลี่ยนชื่อ หรือเขียนทับฟังก์ชันเดิมที่ไม่เกี่ยวข้องกับการสร้าง Rally
5. ห้าม refactor โค้ดเพื่อความสวยงาม ห้ามจัดระเบียบโค้ดใหม่ และห้ามเปลี่ยนสถาปัตยกรรมโดยไม่มีความจำเป็นโดยตรง
6. ห้ามเปลี่ยนระบบ Firebase, PeerJS, Host, ผู้เล่นจริง, บอท, ระบบห้อง, ระบบเทิร์น, ระบบเสียง หรือ Accessibility ที่ทำงานได้อยู่แล้ว เว้นแต่เป็นการปรับเฉพาะจุดที่จำเป็นต่อ Rally ตามข้อกำหนดด้านล่าง
7. ห้ามทำให้ Camping มหาสนุกเดิมเสียหายหรือเปลี่ยนพฤติกรรมการทำงานของเกมเดิม
8. เกม Rally ต้องแยกข้อมูลและห้องออนไลน์ออกจาก Camping อย่างชัดเจน
9. ห้ามสร้างฟังก์ชันหรือพฤติกรรมเพิ่มเติมที่ฉันไม่ได้ระบุไว้
10. หากข้อกำหนดข้อใดไม่สามารถทำได้โดยไม่กระทบระบบเดิม ให้หยุดและอธิบายข้อจำกัดนั้นก่อน ห้ามตัดสินใจเปลี่ยนระบบเอง

## 2. กฎการแก้ไขไฟล์

1. ให้สร้างไฟล์เกม Rally แยกจากไฟล์ Camping โดยใช้ชื่อไฟล์ที่เหมาะสม เช่น `rally.html`, `rally.css` และ `rally.js` หรือชื่อที่สอดคล้องกับโครงสร้างจริงของโปรเจกต์
2. ห้ามแก้ไขไฟล์ Camping ต้นฉบับโดยตรง
3. ให้ใช้ `RallyQuestions.js` เป็นไฟล์คลังคำถามของ Rally ตามโครงสร้างจริงที่ตรวจพบ
4. ห้ามเขียนคำถามขึ้นใหม่แทนคำถามในไฟล์โดยพลการ
5. ห้ามเปลี่ยนข้อความคำถาม ตัวเลือก หรือเฉลยใน `RallyQuestions.js` เว้นแต่ฉันจะสั่งให้แก้ไขโดยตรง
6. หากพบข้อผิดพลาดหรือข้อมูลไม่ชัดเจนในไฟล์คำถาม ให้รายงานแยกต่างหาก ห้ามแก้ไขเนื้อหาเอง
7. ห้ามย้ายโค้ดหรือข้อมูลที่ไม่จำเป็นต่อ Rally ไปยังไฟล์ใหม่
8. ต้องตรวจสอบการอ้างอิงไฟล์ CSS, JavaScript, รูปภาพ และเสียงให้ถูกต้องกับตำแหน่งจริง

## 3. กฎการส่งไฟล์กลับ

เมื่อดำเนินการเสร็จแล้ว ต้องส่งไฟล์ที่แก้ไขหรือสร้างใหม่กลับมาให้ครบทุกไฟล์ที่จำเป็นต่อการใช้งานจริง

* ส่งเนื้อหาไฟล์เต็มตั้งแต่บรรทัดแรกจนถึงบรรทัดสุดท้าย
* ห้ามตัดทอนโค้ดแม้แต่ส่วนเดียว
* ห้ามใช้ข้อความแทนโค้ด เช่น `...`, `โค้ดเดิม`, `ส่วนอื่นเหมือนเดิม`, `ละไว้`, `ต่อจากเดิม` หรือ `[...]`
* ห้ามส่งเฉพาะส่วนที่เปลี่ยนแปลง
* ห้ามละฟังก์ชันเดิมที่จำเป็นต่อการทำงาน
* ห้ามส่งโค้ดตัวอย่างที่ยังไม่สามารถนำไปใช้จริง
* ห้ามกล่าวว่าไฟล์สมบูรณ์หรือทดสอบผ่าน หากยังไม่ได้ตรวจสอบจริง

ต้องระบุชื่อไฟล์แต่ละไฟล์ให้ชัดเจน และแจ้งวิธีวางไฟล์หรือโครงสร้างโฟลเดอร์ที่จำเป็นต่อการใช้งาน

# 4. ชื่อเกมและระบบห้องออนไลน์

ชื่อเกมใหม่คือ **Rally ทั่วไทย**

ให้นำระบบห้องออนไลน์จาก Camping มาใช้ต่อ แต่ต้องแยกพื้นที่ข้อมูลของ Rally ออกจาก Camping โดยเด็ดขาด

## Game ID

ให้ใช้รูปแบบ Game ID ดังนี้

* `Rally00001`
* `Rally00002`
* `Rally00003`
* ไล่ลำดับต่อไปเรื่อย ๆ ตามระบบสร้างห้องเดิมของ Camping

ข้อกำหนด:

1. ใช้ Firebase API และการตั้งค่าการเชื่อมต่อ Firebase ชุดเดิมจาก Camping
2. ห้ามเปลี่ยน API key, Firebase project, configuration หรือข้อมูลเชื่อมต่อเดิมเอง
3. ให้แยก namespace, collection, path หรือกลไกจัดเก็บห้องของ Rally ตามรูปแบบที่เหมาะสมกับระบบจริง เพื่อไม่ให้ห้อง Rally ปรากฏในรายการห้อง Camping และไม่ให้ห้อง Camping ปรากฏในรายการห้อง Rally
4. ห้ามใช้ Game ID ของ Camping กับ Rally
5. การสร้างห้องใหม่ต้องไม่ทำให้ ID ชนกันภายในระบบ Rally
6. ต้องตรวจสอบระบบสร้างห้องและรายการห้องจริงก่อนนำมาใช้ต่อ ห้ามสมมติว่าการเปลี่ยนเฉพาะข้อความ Game ID จะทำให้ข้อมูลแยกจากกันได้
7. ให้คงระบบ Host, ผู้เล่นจริง, บอท, การเข้าร่วมห้อง, การออกจากห้อง และการซิงก์ข้อมูลเดิมไว้เท่าที่เข้ากับ Rally
8. ต้องไม่ทำให้ผู้เล่นในห้องเดียวกันได้รับสถานะกระดาน ตำแหน่งรถ น้ำมัน หรือเทิร์นไม่ตรงกัน

## จำนวนตัวละคร

เกม Rally รองรับผู้เล่นรวมสูงสุด **6 ตัวละครต่อห้อง** โดยนับทั้งผู้เล่นจริงและบอทตามหลักการนับผู้เล่นของ Camping

ห้ามเพิ่มจำนวนตัวละครเกิน 6 ตัว และห้ามทำให้ระบบเดิมนับบอทผิดพลาด

# 5. ระบบเสียง

ให้ใช้ระบบเสียงจาก Camping มหาสนุกแบบเดิม 100% ทั้งในส่วนของโครงสร้างการเล่นเสียง ระบบคิวเสียง และแนวทางการเรียกใช้งาน

## ไฟล์เสียงหลักที่ต้องใช้เหมือนเดิม

* `1.mp3`
* `start.mp3`
* `bgm.mp3`
* `select.mp3`
* `win.mp3`

ข้อกำหนด:

1. ไฟล์เสียงทั้งหมดอยู่ในโฟลเดอร์ `audio` ตำแหน่งเดิมตามโครงสร้างของ Camping
2. ใช้ Web Audio API ทั้งหมดตามระบบเดิม
3. คงวิธีจัดการ AudioContext, การปลดล็อกเสียง, การเล่นเสียง, การหยุดเสียง และการจัดการคิวเสียงตามโค้ดต้นแบบ
4. คง Timing ของเสียงตาม Camping ไว้ก่อน ห้ามปรับเวลาเอง
5. ห้ามเปลี่ยนวิธีเล่นเสียงเป็นระบบอื่น
6. ห้ามใช้ `setTimeout` เพื่อเดาระยะเวลาของเสียงแทนกลไกเดิม หากต้นแบบมีระบบจัดการเสียงที่ถูกต้องอยู่แล้ว
7. ห้ามเพิ่มเสียงใหม่หรือเปลี่ยนชื่อไฟล์เสียงเอง
8. เสียงประกอบอื่น ๆ ที่ยังไม่ได้กำหนด ให้เว้นไว้ตามความเหมาะสมของโครงสร้างเดิม โดยฉันจะกำหนดไฟล์เสียงเพิ่มเติมภายหลัง
9. ห้ามทำให้ปุ่มเสียงหรือกลไกฟื้นฟูเสียงเดิมของเกมหายไป
10. ห้ามสร้างหน้าต่างหรือคอนโซลเพิ่มเติมสำหรับจัดการเสียง

# 6. แนวคิดและเป้าหมายของเกม Rally ทั่วไทย

เกม Rally ทั่วไทยเป็นเกมแข่งรถเดินทางผ่านจังหวัดต่าง ๆ ของประเทศไทย ผู้เล่นต้องเดินทางจากจังหวัดเริ่มต้นไปยังจังหวัดปลายทาง โดยบริหารน้ำมัน ตอบคำถามประจำจังหวัด และใช้จุดแวะพักระหว่างทาง

เป้าหมายของผู้เล่นคือเดินทางไปถึงจังหวัดปลายทางของการแข่งขันให้สำเร็จตามกติกา

ให้ใช้ระบบเทิร์น การทอยลูกเต๋า ผู้เล่นจริง บอท การซิงก์สถานะ และ Accessibility จาก Camping เป็นฐาน แล้วปรับเฉพาะกติกาที่จำเป็นต่อ Rally

## การสุ่มจังหวัด

ประเทศไทยมี 77 หน่วยระดับจังหวัดเมื่อนับกรุงเทพมหานครรวมด้วย

ให้สุ่มเลือกจังหวัดมาใช้ในเกมละ 54 จังหวัด โดยมีข้อกำหนดดังนี้

1. จังหวัดเริ่มต้นและจังหวัดปลายทางต้องเป็นจังหวัดคนละจังหวัดกัน
2. จังหวัดเริ่มต้นและจังหวัดปลายทางต้องอยู่ในชุดจังหวัด 54 จังหวัดที่สุ่มเลือก
3. ให้สุ่มจังหวัดเริ่มต้นและปลายทางใหม่ทุกครั้งที่เริ่มเกมใหม่
4. จังหวัดที่ปรากฏในเกมเดียวกันต้องไม่ซ้ำกัน เว้นแต่มีข้อกำหนดที่ระบุไว้ในไฟล์ต้นแบบและจำเป็นต้องคงไว้ ซึ่งต้องรายงานก่อน
5. จังหวัดและตำแหน่งช่องต้องเหมือนกันสำหรับผู้เล่นทุกคนในห้องเดียวกัน
6. ให้ Host เป็นผู้สร้างหรือกำหนดชุดเส้นทางกลาง และซิงก์ไปยังผู้เล่นทุกคน
7. ห้ามให้แต่ละเครื่องสุ่มจังหวัดหรือช่องกระดานแยกกันเองจนทำให้เส้นทางไม่ตรงกัน
8. เมื่อเริ่มเกมใหม่ ให้สุ่มเส้นทางและตำแหน่งช่องใหม่
9. การสุ่มต้องไม่ทำให้จำนวนช่องจังหวัด ปั๊มน้ำมัน หรือจุดแวะพักผิดจากจำนวนที่กำหนด
10. ให้จัดวางช่องอย่างสมดุล ไม่ให้ช่องประเภทเดียวกันกระจุกตัวเกินไป โดยไม่เปลี่ยนจำนวนช่องที่กำหนด

## การแสดงกระดาน

* ใช้กระดาน 80 ช่อง
* แสดงช่องจังหวัดและจุดแวะพักตามประเภทจริง
* แสดงตำแหน่งรถของผู้เล่นแต่ละคนให้ตรงกับสถานะกลาง
* ต้องรองรับผู้เล่นสูงสุด 6 ตัวละคร
* การเปลี่ยนตำแหน่งรถต้องอัปเดตตรงกันทุกอุปกรณ์
* ห้ามให้กระดานที่ผู้เล่นแต่ละคนเห็นมีเส้นทางไม่ตรงกัน

# 8. ระบบน้ำมัน

รถของผู้เล่นแต่ละคนมีน้ำมันสูงสุด **10 ขีด**

| เหตุการณ์                   | ผลต่อน้ำมัน                            |
| --------------------------- | -------------------------------------- |
| เริ่มเกม                    | มีน้ำมันเต็มถัง 10 ขีด                 |
| ทอยลูกเต๋าเพื่อเดินแต่ละรอบ | ใช้น้ำมัน 3 ขีด                        |
| ตอบคำถามจังหวัดถูก          | เติมน้ำมัน 2 ขีด แต่ไม่เกิน 10         |

| ตกช่องแวะพักทั่วไป          | เติมฟรี 1 ขีด                          |
| น้ำมันหมดและหยุดพัก         | หยุด 1 เทิร์น และได้รับน้ำมันฟรี 3 ขีด |

1. ก่อนทอยลูกเต๋า ต้องตรวจสอบน้ำมันของผู้เล่นที่ถึงเทิร์น
2. หากผู้เล่นมีน้ำมันไม่เพียงพอสำหรับการทอย ให้ถือว่ารถน้ำมันหมด
3. ผู้เล่นต้องหยุดเล่น 1 เทิร์น
4. ให้เปลี่ยนไปยังผู้เล่นคนถัดไปทันที
5. ผู้เล่นที่น้ำมันหมดได้รับน้ำมันฟรี 3 ขีดจากการหยุดพัก
6. เมื่อถึงเทิร์นถัดไป ผู้เล่นสามารถเล่นต่อได้ตามปกติ
7. การทอยครั้งถัดไปยังคงใช้น้ำมัน 3 ขีดตามกติกาปกติ
8. ห้ามหักน้ำมันซ้ำจากเหตุการณ์เดียวกัน
9. ห้ามให้ผู้เล่นทอยได้หากน้ำมันไม่เพียงพอ
10. การหยุดพักและการเพิ่มน้ำมันต้องซิงก์ตรงกันทุกอุปกรณ์

# 9. ระบบคำถามประจำจังหวัด

ไฟล์คลังคำถามของเกมคือ **`RallyQuestions.js`**

ไฟล์นี้เป็นแหล่งข้อมูลหลักสำหรับคำถาม ตัวเลือก และคำตอบที่ถูกต้องของแต่ละจังหวัด

## ข้อกำหนดการเรียกใช้คำถาม

1. ต้องอ่านและตรวจสอบโครงสร้างจริงของ `RallyQuestions.js` ก่อนเขียนระบบเชื่อมต่อ
2. ห้ามสมมติชื่ออาร์เรย์ ชื่อฟังก์ชัน รูปแบบ Object หรือชื่อฟิลด์เอง
3. ให้เรียกคำถามจากข้อมูลจริงในไฟล์ โดยใช้จังหวัดที่รถตกอยู่เป็นตัวกำหนด
4. เมื่อรถเข้าช่องจังหวัดใด ต้องสุ่มคำถามจากจังหวัดนั้นเท่านั้น
5. ห้ามนำคำถามของจังหวัดอื่นมาใช้แทน
6. ห้ามสุ่มคำถามจากคลังรวมโดยไม่กรองจังหวัด
7. ให้สุ่มคำถามมา **1 ข้อต่อการเข้าช่องจังหวัดแต่ละครั้ง**
8. คำถามหนึ่งข้อมีตัวเลือก 3 ตัวเลือกตามข้อมูลต้นฉบับ
9. ต้องมีคำตอบที่ถูกต้องเพียงหนึ่งเดียว
10. ห้ามแก้ข้อความคำถาม ตัวเลือก หรือเฉลยในไฟล์โดยพลการ
11. ห้ามสร้างตัวเลือกใหม่หรือเติมคำตอบที่ไม่มีอยู่ในไฟล์
12. หากจังหวัดใดไม่มีคำถาม หรือข้อมูลผิดรูปแบบ ให้จัดการด้วยวิธีที่ไม่ทำให้เกมพัง และรายงานปัญหาให้ฉันทราบ ห้ามสร้างคำถามปลอมขึ้นมาแทน
13. ให้หลีกเลี่ยงการสุ่มคำถามซ้ำภายในเกมเดียวกันเท่าที่ข้อมูลในคลังคำถามรองรับ
14. หากคำถามของจังหวัดนั้นถูกใช้หมดแล้ว ให้จัดการตามโครงสร้างที่ปลอดภัย โดยห้ามทำให้คำตอบหรือจังหวัดผิดพลาด
15. หากมีคำถามที่ข้อมูลไม่ครบหรือมีคำตอบไม่ชัดเจน ห้ามนำมาใช้โดยเดาเอง

## การสลับตัวเลือก

เพื่อไม่ให้ผู้เล่นจำตำแหน่งคำตอบได้ ให้สลับลำดับตัวเลือกในแต่ละครั้งที่แสดงคำถาม

ข้อกำหนดสำคัญ:

* ต้องสลับเฉพาะลำดับการแสดงตัวเลือก ไม่เปลี่ยนเนื้อหาของตัวเลือก
* ต้องรักษาความสัมพันธ์ระหว่างตัวเลือกกับคำตอบที่ถูกต้องให้ถูกต้องเสมอ
* หลังสลับแล้ว ต้องมีคำตอบที่ถูกต้องเพียงหนึ่งเดียว
* ห้ามยึดตำแหน่งคำตอบเดิม เช่น A, B หรือ C เป็นตัวตัดสินคำตอบหลังสลับ
* ให้ตรวจสอบจากข้อมูลเฉลยจริงของคำถาม
* การสลับต้องทำงานได้ทุกครั้งที่มีการสุ่มคำถาม โดยไม่ทำให้เฉลยคลาดเคลื่อน
* ต้องให้ Host ตรวจสอบคำตอบและกำหนดผลกลาง เพื่อป้องกันการตัดสินผลต่างกันระหว่างอุปกรณ์
* ห้ามให้ผู้เล่นที่ใช้ Screen Reader ได้รับตัวเลือกคนละชุดกับผู้เล่นที่มองเห็น

## การแสดงคำถามและการเข้าถึง

* แสดงชื่อจังหวัดที่กำลังตอบคำถามอย่างชัดเจน
* แสดงคำถามและตัวเลือกครบถ้วน
* ปุ่มตัวเลือกต้องใช้งานได้ด้วยคีย์บอร์ดและ Screen Reader
* ต้องมีชื่อปุ่มหรือ Accessible Name ที่สื่อความหมาย
* ผู้เล่นต้องทราบว่ากำลังตอบคำถามข้อใดและมีตัวเลือกอะไรบ้าง
* เมื่อเลือกคำตอบแล้ว ต้องประกาศผลถูกหรือผิดอย่างเหมาะสม
* ห้ามประกาศข้อความซ้ำโดยไม่จำเป็น
* ต้องคงแนวทาง ARIA live และระบบประกาศจาก Camping ให้มากที่สุด

# 10. ผลของการตอบคำถามจังหวัด

เมื่อผู้เล่นเข้าช่องจังหวัด ให้แสดงคำถามของจังหวัดนั้น และรอให้ผู้เล่นตอบคำถาม

## เมื่อตอบถูก

1. เติมน้ำมัน 2 ขีด แต่ห้ามเกิน 10 ขีด
2. สุ่มระยะเดินหน้า 2–5 ช่อง
3. เคลื่อนรถไปตามระยะที่สุ่มได้
4. ตรวจสอบช่องปลายทางตามกติกาของช่องนั้น
5. หากถึงจังหวัดปลายทาง ให้จบการแข่งขันทันที

## เมื่อตอบผิด

1. ไม่ได้รับน้ำมันเพิ่ม
2. สุ่มระยะถอยหลัง 1–3 ช่อง
3. เคลื่อนรถถอยหลังตามระยะที่สุ่มได้
4. หากถอยหลังเกินช่องเริ่มต้น ให้หยุดที่ช่อง 1
5. ห้ามให้รถถอยออกนอกกระดาน

## ข้อกำหนดเพิ่มเติม

* ให้ใช้ระยะเดินหน้าและถอยหลังตามค่าตั้งต้นข้างต้น
* ห้ามเปลี่ยนช่วงระยะสุ่มเอง
* ห้ามให้ผลคำถามหนึ่งข้อทำงานซ้ำหลายครั้ง
* ห้ามให้ผู้เล่นตอบคำถามเดียวกันซ้ำในเทิร์นเดียวกัน
* ต้องซิงก์คำถาม ตัวเลือก ผลคำตอบ น้ำมัน และตำแหน่งรถให้ตรงกัน
* หากเกิดการเชื่อมต่อซ้ำหรือได้รับข้อความซ้ำ ต้องป้องกันการนำผลเดิมไปใช้ซ้ำ

# 11. ปั๊มน้ำมันและจุดแวะพัก

## ปั๊มน้ำมัน — 10 ช่อง

เมื่อรถตกช่องปั๊มน้ำมัน:

1. เติมน้ำมันฟรีจนเต็มถัง 10 ขีด
2. รถต้องหยุดที่ช่องปั๊มน้ำมันทันที
3. หากยังมีระยะเดินเหลือจากการเคลื่อนที่ครั้งนั้น ให้ยกเลิกระยะที่เหลือ
4. ห้ามเคลื่อนรถต่อผ่านช่องปั๊มน้ำมันในเหตุการณ์เดียวกัน

## จุดแวะพัก — อย่างละ 2 ช่อง

* คาเฟ่ริมทาง
* โรงแรมจิ้งหรีด
* ห้องน้ำกลางทุ่ง
* ร้านข้าวแกง 24 ชั่วโมง
* ร้านตัดผมสุดสยอง
* Car care สกปรก
* อู่ซ่อมรถร้าง
* โรงน้ำชา

เมื่อรถตกช่องแวะพักเหล่านี้:

1. เติมน้ำมันฟรี 1 ขีด โดยไม่เกิน 10 ขีด
2. หยุดรถที่ช่องนั้นทันที
3. ไม่มีผลพิเศษอื่น
4. ห้ามเพิ่มการสุ่มเหตุการณ์หรือการลงโทษที่ไม่ได้กำหนด
5. ต้องแสดงข้อความหรือประกาศประเภทช่องให้เหมาะสม โดยไม่รบกวนการเล่นเกินจำเป็น

# 12. ลำดับการเล่นในแต่ละเทิร์น

ให้ใช้ลำดับการทำงานดังนี้อย่างเคร่งครัด

1. ตรวจสอบว่าเป็นเทิร์นของผู้เล่นคนใด
2. ตรวจสอบว่าสถานะเกมยังไม่จบ
3. ตรวจสอบน้ำมันของผู้เล่น
4. หากน้ำมันไม่เพียงพอ ให้ใช้กติกาน้ำมันหมดและข้ามเทิร์น
5. หากน้ำมันเพียงพอ ให้หักน้ำมัน 3 ขีด
6. ให้ผู้เล่นทอยลูกเต๋า
7. เคลื่อนรถตามแต้มลูกเต๋า
8. ตรวจสอบช่องที่รถเข้า
9. หากเป็นช่องจังหวัด ให้สุ่มคำถามของจังหวัดนั้น 1 ข้อและให้ผู้เล่นตอบ
10. หากตอบถูกหรือผิด ให้ดำเนินการตามผลคำถาม
11. หากเป็นช่องปั๊มน้ำมัน ให้เติมน้ำมันเต็มถังและหยุดที่ช่องนั้น
12. หากเป็นช่องแวะพัก ให้เติมน้ำมัน 1 ขีดและหยุดที่ช่องนั้น
13. หากมีการเดินหน้า ถอยหลัง หรือสะท้อนกลับ ให้ตรวจสอบช่องที่รถไปถึงตามกติกา
14. หากถึงจังหวัดปลายทาง ให้จบการแข่งขันทันที
15. หากเกมยังไม่จบ ให้เปลี่ยนไปยังผู้เล่นคนถัดไป

ห้ามข้ามลำดับขั้นตอนที่จำเป็นต่อการตัดสินผล และห้ามให้เหตุการณ์เดียวกันถูกประมวลผลซ้ำ

# 13. กติกาการเคลื่อนที่บนกระดาน

## การถอยหลัง

* หากถอยหลังเกินช่องเริ่มต้น ให้หยุดที่ช่อง 1
* ห้ามให้ตำแหน่งรถน้อยกว่า 1
* ต้องอัปเดตตำแหน่งรถให้ตรงกันทุกอุปกรณ์

## การเดินหน้าเกินช่อง 80

ให้ใช้กติกาสะท้อนกลับจากปลายกระดาน

ตัวอย่าง:

* หากอยู่ช่อง 79 และเดินหน้า 9 ช่อง ให้สะท้อนกลับมาอยู่ช่อง 72

ต้องใช้กติกานี้กับการเดินหน้าที่เกิดจากผลคำถามและการเคลื่อนที่อื่น ๆ ที่ระบุไว้ในเกม

## การหยุดรถ

* เมื่อตกช่องปั๊มน้ำมัน ต้องหยุดทันที
* เมื่อตกช่องแวะพัก ต้องหยุดทันที
* หากถึงจังหวัดปลายทาง ให้จบเกมทันที
* ห้ามเดินต่อหลังจากเข้าเส้นชัย
* ห้ามสุ่มคำถามหรือเหตุการณ์ต่อเนื่องหลังจบเกม

# 14. ระบบผู้เล่นจริง บอท และ Host

ให้คงระบบผู้เล่นจริง บอท และ Host จาก Camping ไว้ โดยปรับเฉพาะสิ่งที่จำเป็นต่อเกม Rally

1. ผู้เล่นจริงและบอทใช้กติกาน้ำมันเดียวกัน
2. ผู้เล่นจริงและบอทใช้กติกาการทอยลูกเต๋าเดียวกัน
3. ผู้เล่นจริงและบอทใช้กติกาการตอบคำถามเดียวกัน
4. ผู้เล่นจริงและบอทใช้กติกาปั๊มน้ำมันและจุดแวะพักเดียวกัน
5. บอทต้องไม่สามารถทำสิ่งที่ผู้เล่นจริงทำไม่ได้
6. บอทต้องตอบคำถามตามระบบตัดสินใจที่เหมาะสม โดยไม่เปลี่ยนเฉลยจริง
7. บอทต้องไม่ตอบคำถามแทนผู้เล่นจริง
8. ให้ Host เป็นผู้ตัดสินผลกลางของเกม
9. สถานะตำแหน่งรถ น้ำมัน เทิร์น คำถาม ผลคำตอบ และสถานะการแข่งขันต้องซิงก์ตรงกันทุกเครื่อง
10. ต้องป้องกันการประมวลผลผลการเล่นซ้ำจากข้อความเครือข่ายซ้ำ
11. ให้คงระบบจัดการผู้เล่นหลุด การกลับเข้าห้อง และการเปลี่ยนสถานะผู้เล่นจาก Camping เท่าที่ใช้ได้กับ Rally
12. ห้ามให้ผู้เล่นที่หลุดจากห้องทำให้สถานะเกมของผู้เล่นคนอื่นเสียหาย

# 15. ระบบ Screen Reader และ Accessibility

Accessibility เป็นข้อกำหนดสำคัญ ห้ามลดทอนความสามารถจาก Camping โดยไม่มีเหตุจำเป็น

ต้องคงแนวทางเดิมในเรื่องต่อไปนี้:

* NVDA
* JAWS
* VoiceOver
* การใช้งานด้วยคีย์บอร์ด
* การกำหนด Focus
* ARIA labels
* ARIA live regions
* ระบบคิวประกาศ
* การประกาศเทิร์น
* การประกาศผลการเล่น
* การประกาศสถานะสำคัญ

## ข้อกำหนด

1. ห้ามลบ ARIA attributes ที่ยังจำเป็น
2. ห้ามเปลี่ยนข้อความประกาศเดิมโดยไม่จำเป็น
3. ห้ามเพิ่มการประกาศซ้ำจนรบกวนผู้เล่น
4. ต้องประกาศข้อมูลสำคัญ เช่น ผู้เล่นที่ถึงเทิร์น ผลลูกเต๋า ผลคำถาม น้ำมัน และการจบเกม
5. ผู้เล่นที่มองเห็นและผู้เล่นที่ใช้ Screen Reader ต้องได้รับข้อมูลเกมที่สอดคล้องกัน
6. ปุ่มทุกปุ่มที่จำเป็นต้องใช้งานต้องมีชื่อที่เข้าใจได้
7. ต้องสามารถใช้งานส่วนสำคัญของเกมได้โดยไม่จำเป็นต้องใช้เมาส์
8. ห้ามซ่อนข้อมูลสำคัญจาก Screen Reader
9. ห้ามทำให้ Focus หลุดหรือค้างหลังแสดงคำถามหรือเปลี่ยนสถานะเกม
10. ให้คงรูปแบบการประกาศและ Timing เดิมจาก Camping ให้มากที่สุด

# 16. รูปแบบหน้าจอและส่วนติดต่อผู้เล่น

ให้ใช้รูปแบบหน้าจอและแนวทาง UX จาก Camping เป็นพื้นฐาน โดยปรับข้อความและองค์ประกอบที่จำเป็นต่อ Rally

* เปลี่ยนชื่อเกมและข้อความที่เกี่ยวข้องให้เป็น Rally ทั่วไทย
* ใช้ระบบกรอกชื่อผู้เล่นและการเข้าห้องตาม Camping
* คงรูปแบบ Lobby และการจัดการผู้เล่นตามต้นแบบ
* แสดงรายชื่อผู้เล่นจริงและบอทให้ถูกต้อง
* แสดงจำนวนผู้เล่นไม่เกิน 6 ตัวละคร
* แสดงกระดาน 80 ช่อง
* แสดงตำแหน่งรถของผู้เล่นทุกคน
* แสดงสถานะน้ำมันของผู้เล่น
* แสดงคำถามและตัวเลือกเมื่อรถเข้าช่องจังหวัด
* แสดงผลคำถามและเหตุการณ์อย่างเข้าใจง่าย
* ห้ามเพิ่มหน้าต่างหรือเมนูที่ไม่ได้กำหนด
* ห้ามเปลี่ยนรูปแบบการใช้งานเดิมที่ไม่เกี่ยวข้องกับ Rally

หากต้องแก้ CSS ให้ทำเฉพาะส่วนที่จำเป็นต่อการแสดงกระดาน รถ คำถาม และสถานะ Rally โดยไม่เปลี่ยนส่วนอื่นโดยพลการ

# 17. การซิงก์ข้อมูลและความถูกต้องของเกม

ให้ Host เป็นผู้ตัดสินผลกลาง และซิงก์สถานะไปยังผู้เล่นทุกคน

ข้อมูลที่ต้องตรงกันทุกอุปกรณ์ ได้แก่

* Game ID และห้องที่กำลังเล่น
* รายชื่อผู้เล่นและบอท
* ลำดับเทิร์น
* ชุดจังหวัดและเส้นทาง
* ประเภทช่องบนกระดาน
* ตำแหน่งรถของผู้เล่นแต่ละคน
* น้ำมันของผู้เล่นแต่ละคน
* คำถามที่กำลังแสดง
* ตัวเลือกที่กำลังแสดง
* ผลคำตอบ
* ผลการเคลื่อนที่
* สถานะปั๊มน้ำมันและจุดแวะพัก
* สถานะการแข่งขัน
* ผู้ชนะ

ห้ามให้ผู้เล่นแต่ละเครื่องคำนวณผลสุ่มหรือผลคำถามแยกกันจนเกิดผลไม่ตรงกัน

การสุ่มที่มีผลต่อการแข่งขันต้องถูกกำหนดจากแหล่งกลางตามระบบ Host ของ Camping และส่งผลไปยังผู้เล่นทุกคน

# 18. การจบเกม

เมื่อผู้เล่นเดินทางถึงจังหวัดปลายทาง ให้จบการแข่งขันทันที

1. ระบุผู้ชนะให้ชัดเจน
2. แสดงสถานะการแข่งขันว่าจบแล้ว
3. ประกาศผลให้ผู้เล่นทุกคนทราบ
4. ใช้ไฟล์เสียง `win.mp3` ตามระบบเสียงเดิม
5. ห้ามสุ่มคำถามหรือเหตุการณ์ต่อหลังเข้าเส้นชัย
6. ห้ามให้ผู้เล่นคนอื่นเดินต่อหลังเกมจบ
7. ต้องซิงก์ผลการแข่งขันให้ตรงกันทุกอุปกรณ์
8. คงแนวทางหน้าจอจบเกมและปุ่มที่เกี่ยวข้องจาก Camping เท่าที่เหมาะสมกับ Rally
9. ห้ามเพิ่มเงื่อนไขการชนะอื่นที่ไม่ได้กำหนดไว้

# 19. การตรวจสอบก่อนส่งมอบ

ก่อนส่งไฟล์กลับ ต้องตรวจสอบโค้ดและความสอดคล้องกับข้อกำหนดทั้งหมด

## ตรวจสอบโครงสร้าง

* ไฟล์ HTML อ้างอิงไฟล์ CSS และ JavaScript ถูกต้อง
* `RallyQuestions.js` ถูกโหลดและเชื่อมต่ออย่างถูกต้อง
* การอ้างอิงไฟล์เสียงในโฟลเดอร์ `audio` ถูกต้อง
* ไม่มีการแก้ไขไฟล์ Camping ต้นฉบับโดยไม่จำเป็น
* ไม่มีการอ้างอิง Game ID ของ Camping ในระบบห้อง Rally

## ตรวจสอบกติกา

* กระดานมี 80 ช่องตรงตามจำนวนที่กำหนด
* มีจังหวัด 54 ช่อง
* มีปั๊มน้ำมัน 10 ช่อง
* มีจุดแวะพักแต่ละประเภทอย่างละ 2 ช่อง
* จังหวัดเริ่มต้นและปลายทางไม่ใช่จังหวัดเดียวกัน
* จังหวัดในเกมเดียวกันไม่ซ้ำกัน
* ผู้เล่นสูงสุด 6 ตัวละคร
* น้ำมันเริ่มต้น 10 ขีด
* ใช้น้ำมัน 3 ขีดต่อการทอย
* ตอบถูกเติม 2 ขีด
* ตอบผิดไม่เติมน้ำมัน
* ปั๊มน้ำมันเติมเต็มถัง
* จุดแวะพักเติม 1 ขีด
* น้ำมันหมดหยุด 1 เทิร์นและได้รับ 3 ขีด
* ระยะเดินหน้าและถอยหลังตรงตามที่กำหนด
* การสะท้อนกลับจากช่อง 80 ทำงานถูกต้อง
* เมื่อถึงจังหวัดปลายทางต้องจบเกมทันที

## ตรวจสอบคำถาม

* คำถามตรงกับจังหวัดที่รถตก
* สุ่มคำถามเพียง 1 ข้อในแต่ละครั้ง
* มีตัวเลือก 3 ตัวเลือก
* สลับลำดับตัวเลือกได้
* เฉลยยังถูกต้องหลังสลับตัวเลือก
* ไม่มีการสร้างคำถามหรือเฉลยขึ้นเอง
* ไม่มีการตอบคำถามซ้ำโดยไม่ตั้งใจ
* ผู้เล่นทุกคนเห็นคำถามและตัวเลือกชุดเดียวกัน

## ตรวจสอบระบบออนไลน์และ Accessibility

* ห้อง Rally ไม่ปรากฏใน Camping
* ห้อง Camping ไม่ปรากฏใน Rally
* ผู้เล่นจริงและบอททำงานตามกติกาเดียวกัน
* สถานะซิงก์ตรงกันทุกอุปกรณ์
* ระบบเสียงใช้ Web Audio API ตามต้นแบบ
* คีย์บอร์ดและ Screen Reader ใช้งานได้
* ไม่มีการประกาศซ้ำโดยไม่จำเป็น
* ไม่มีการประมวลผลเหตุการณ์เดียวกันซ้ำ
* ไม่มีข้อผิดพลาด JavaScript ที่ตรวจพบได้

หากยังไม่ได้ทดสอบกับ Firebase, PeerJS หรืออุปกรณ์จริง ให้ระบุอย่างตรงไปตรงมาว่าส่วนใดตรวจสอบแล้วและส่วนใดยังไม่ได้ทดสอบ ห้ามกล่าวอ้างว่าผ่านการทดสอบจริงโดยไม่มีหลักฐาน

# 20. รูปแบบคำตอบที่ต้องส่งกลับ

เมื่อทำงานเสร็จ ให้ตอบกลับตามลำดับนี้

1. สรุปสั้น ๆ ว่ามีการสร้างหรือแก้ไขไฟล์ใดบ้าง
2. ระบุโครงสร้างโฟลเดอร์และตำแหน่งที่ต้องวางไฟล์
3. ส่งไฟล์ HTML ฉบับเต็ม
4. ส่งไฟล์ CSS ฉบับเต็ม
5. ส่งไฟล์ JavaScript ฉบับเต็ม
6. หากมีไฟล์อื่นที่จำเป็นต่อการใช้งาน ให้ส่งให้ครบ
7. แจ้งผลการตรวจสอบตามรายการในหัวข้อ 19
8. ระบุข้อจำกัดหรือสิ่งที่ยังไม่ได้ทดสอบอย่างชัดเจน

**ห้ามส่งเฉพาะตัวอย่างหรือเฉพาะส่วนที่แก้ไข ต้องส่งไฟล์เต็มที่นำไปใช้งานต่อได้จริง**

## คำสั่งสุดท้าย

ให้เริ่มจากการตรวจสอบ Camping ทั้ง 3 ไฟล์และ `RallyQuestions.js` ที่แนบมาอย่างละเอียดก่อน แล้วจึงพัฒนา Rally ทั่วไทยตามข้อกำหนดทั้งหมดนี้

ให้ถือว่าระบบ Camping เดิมเป็นระบบที่ใช้งานได้อยู่แล้ว และมีหน้าที่ปรับให้เป็นเกม Rally โดยรักษาความสามารถเดิมให้มากที่สุด

**แก้เฉพาะสิ่งที่จำเป็นต่อ Rally เท่านั้น ห้ามเปลี่ยนแปลงสิ่งอื่น ห้ามคิดกติกาเพิ่มเอง ห้ามตัดทอนโค้ด และต้องส่งไฟล์เต็มครบทุกไฟล์**

หากพบความขัดแย้งระหว่างข้อกำหนดกับโค้ดต้นแบบ ห้ามเลือกแก้เองโดยพลการ ให้รายงานความขัดแย้งและถามฉันก่อนดำเนินการในส่วนนั้น
