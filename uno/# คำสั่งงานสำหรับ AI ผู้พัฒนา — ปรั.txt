# คำสั่งงานสำหรับ AI ผู้พัฒนา — ปรับปรุงเกม UNO (ไฟล์ `uno.html`)

## กฎเหล็ก (ต้องอ่านและปฏิบัติตามอย่างเคร่งครัด)
1. **แก้ไขเฉพาะสิ่งที่ระบุไว้ด้านล่างนี้เท่านั้น** ห้ามแตะต้อง แก้ไข ปรับ refactor เปลี่ยนชื่อตัวแปร/ฟังก์ชัน/id, เปลี่ยนสไตล์ หรือ "ปรับปรุงให้ดีขึ้น" ส่วนใดๆ ที่ไม่ได้อยู่ในรายการนี้ แม้จะเห็นว่าโค้ดส่วนอื่นดูปรับปรุงได้ก็ตาม
2. ฟีเจอร์ ระบบ และพฤติกรรมเดิมทั้งหมดที่ไม่เกี่ยวข้องกับรายการด้านล่าง **ต้องทำงานเหมือนเดิม 100%** (multiplayer sync ผ่าน PeerJS/Firebase, การ์ดพิเศษ, ระบบ challenge, accessibility/aria, ระบบเสียง ฯลฯ)
3. ห้ามลบหรือย้าย element ที่ไม่เกี่ยวข้อง ห้ามเปลี่ยนโครงสร้าง DOM ของหน้าจออื่นที่ไม่ใช่หน้าจอผลลัพธ์ (`#screen-result`)
4. เมื่อแก้เสร็จ ให้ส่งไฟล์ `uno.html` กลับมาทั้งไฟล์ (ฉบับสมบูรณ์ พร้อมใช้งานจริงทันที) ไม่ใช่ diff บางส่วน

ไฟล์เป้าหมาย: `uno.html` — เกม UNO เล่นแบบ real-time ผ่าน PeerJS (host/client) และซิงก์สถานะห้องผ่าน Firebase

## รายการที่ต้องแก้ไข

### ข้อ 1: ย้ายแถบสถานะตัวละคร (character status bar) มาแสดงด้านบนสุดของหน้าจอสรุปผล

**ปัญหาปัจจุบัน:** ในหน้าจอ `#screen-result` (ฟังก์ชัน `showResult()`) มีการสร้างแถบสถานะตัวละครที่ element `#result-status-bar` อยู่แล้ว และคะแนนรวม (`playerStates[p.id].score`) ที่แสดงในนั้น **ถูกต้องตรงตามจริงอยู่แล้ว** (อัปเดตสะสมทุกครั้งที่จบตา เหมือนตอนเริ่มเกมใหม่) แต่ตำแหน่งของมันอยู่ **ใต้** หัวข้อ `<h1 id="title-result">` และ `<h2 id="winner-text">` ในขณะที่ระหว่างเล่นเกมจริง แถบสถานะตัวละคร (`#top-status-bar`) จะอยู่ **บนสุด** เหนือหัวข้อรอบ (`#current-turn-heading`)

**สิ่งที่ต้องทำ:**
- จัดลำดับ DOM ใหม่ในหน้าจอ `#screen-result` ให้ `#result-status-bar` ปรากฏเป็นลำดับแรกสุด (บนสุด) แทนที่ `<h1 id="title-result">` และ `<h2 id="winner-text">` — คือให้ตำแหน่งของแถบสถานะตัวละครเมื่อจบเกม อยู่ตำแหน่งเดียวกับตอนเล่นเกม (บนสุดของพื้นที่เนื้อหา)
- ย้าย `<h1 id="title-result">จบเกม!</h1>` และ `<h2 id="winner-text">...</h2>` ให้อยู่ **ถัดลงมาใต้** แถบสถานะ พร้อมปรับระยะห่าง (margin/padding) ให้ดูเป็นลำดับที่สวยงามเป็นธรรมชาติ (ไม่ชิดหรือห่างเกินไป) — เช่นเพิ่ม `margin-top` ให้ h1 หรือปรับ `margin-bottom` ของ `#result-status-bar`
- **ห้ามเปลี่ยน** ตรรกะการคำนวณหรือแสดงคะแนนใน `showResult()` (โค้ดส่วนที่ loop `players.forEach` แล้วสร้าง `charDiv` ด้วย `pState.score`) เพราะคะแนนถูกต้องอยู่แล้ว งานนี้คือ "ย้ายตำแหน่งการแสดงผล" เท่านั้น ไม่ใช่แก้ตรรกะคะแนน
- ยังคงเก็บ id `result-status-bar`, `title-result`, `winner-text` เดิมไว้ทั้งหมด (ห้ามเปลี่ยนชื่อ id เพราะมีการอ้างอิงจาก JS เช่น `switchScreen('screen-result', 'title-result')`)

### ข้อ 2: กติกาชนะเกมแบบสมบูรณ์ที่ 200 คะแนน + ประกาศ "จ้าวแห่ง Uno"

**สิ่งที่ต้องทำ:**

1. **จุดตรวจสอบ:** ตรวจสอบเงื่อนไขนี้ **เฉพาะตอนจบแต่ละตา/รอบ (round)** เท่านั้น คือในฟังก์ชัน `handleWin(winnerId)` หลังบรรทัดที่อัปเดต `game.playerStates[winnerId].score += score;` ให้เช็คทันทีว่า `game.playerStates[winnerId].score >= 200` หรือไม่ (ตรวจเฉพาะฝั่ง host เท่านั้น เหมือนโค้ดเดิมที่ตรรกะเกมทั้งหมดรันที่ host แล้ว broadcast ออกไป)

2. **เมื่อมีผู้เล่นคะแนนรวมถึง/เกิน 200 คะแนน:**
   - ให้ถือว่าเกม "จบสมบูรณ์" (ไม่ใช่แค่จบตา) — ให้ตั้ง flag ใหม่ เช่น `game.matchOver = true` และส่ง flag นี้ไปกับ event `endGame` ที่ broadcast ไปยัง client ทุกคนด้วย (เพิ่ม field เข้าไปใน object ที่ส่งอยู่แล้ว เช่น `connections.forEach(c => { if (c.open) c.send({ type: 'endGame', winnerId, scores: score, matchOver: true }); });`) — **ห้ามแก้โครงสร้าง event เดิมสำหรับกรณีจบตาปกติ (matchOver จะเป็น false/undefined)**
   - สุ่มเลือกประโยคประกาศผู้ชนะเกมจากชุดประโยคต่อไปนี้ (หรือใกล้เคียง โดยแทรกชื่อสีตัวละครผู้ชนะ เช่น `COLORS.find(c => c.id === winner.colorId).name` ซึ่งจะได้ค่าเช่น "สีแดง"):
     1. `ตัวละคร{สี} คือจ้าวแห่ง Uno!`
     2. `ขอแสดงความยินดี! ตัวละคร{สี} ได้ก้าวขึ้นเป็นจ้าวแห่ง Uno!`
     3. `เกมจบสมบูรณ์! ตัวละคร{สี} คว้าตำแหน่งจ้าวแห่ง Uno ไปครอง!`
     4. `ไม่มีใครหยุดได้! ตัวละคร{สี} คือจ้าวแห่ง Uno ตัวจริง!`
     5. `ครองบัลลังก์สำเร็จ ตัวละคร{สี} คือจ้าวแห่ง Uno แห่งห้องนี้!`
   - แสดงประโยคที่สุ่มได้นี้ในหน้าจอสรุปผล เพิ่มเติมจากข้อความคะแนนเดิม (เช่น แสดงต่อท้ายหรือแทนที่ข้อความใน `#winner-text` / เพิ่ม element ใหม่ใต้แถบสถานะที่ย้ายมาในข้อ 1 — เลือกวิธีที่กระทบโค้ดเดิมน้อยที่สุด) โดยที่ **กรณีจบตาปกติ (คะแนนรวมยังไม่ถึง 200) ต้องแสดงผลแบบเดิมทุกประการ ไม่มีข้อความ "จ้าวแห่ง Uno" ปนมา**

3. **ซ่อนปุ่ม "เล่นรอบใหม่" เมื่อเกมจบสมบูรณ์:**
   - ในฟังก์ชัน `showResult(winnerId, score)` ต้องรับรู้ว่าตานี้เป็นการจบเกมสมบูรณ์หรือไม่ (จาก `game.matchOver` ที่ตั้งไว้ในข้อก่อนหน้า ซึ่งทั้งฝั่ง host และ client ต้องเห็นค่าตรงกัน — ฝั่ง client อ่านจาก event `endGame` ที่มี `matchOver` แนบมา)
   - ถ้า `matchOver === true`: element `#result-host-controls` (ที่ครอบปุ่ม `#btn-play-again`) **ต้องไม่แสดงผลเลย แม้แต่กับเจ้าของห้อง (host)** — คือฝั่ง host จะไม่เห็นปุ่ม "เล่นรอบใหม่" อีกต่อไป เหมือนที่ฝั่ง client ไม่เคยเห็นปุ่มนี้อยู่แล้วในโค้ดเดิม
   - ถ้า `matchOver` ไม่ใช่ true (จบตาปกติ ยังเล่นต่อได้): พฤติกรรมเดิมทั้งหมดต้องเหมือนเดิม 100% — host ยังเห็นปุ่ม "เล่นรอบใหม่" ตามปกติ
   - ปุ่ม "กลับหน้าหลัก" (`class="btn-home-main"`, aria-label="กลับสู่ชุมชน") ให้คงอยู่เสมอไม่ว่ากรณีใด (ไม่ต้องแก้ไขปุ่มนี้)

4. **ป้องกันการเริ่มรอบใหม่ซ้ำ:** เนื่องจากปุ่ม `#btn-play-again` ถูกซ่อนไปแล้วเมื่อ `matchOver === true` ก็ไม่จำเป็นต้องเพิ่มการป้องกันซ้ำซ้อนที่อื่น (เช่นไม่ต้องแก้ `initUNOGame()`) — ให้คงฟังก์ชันเดิมไว้ทั้งหมด เพราะเมื่อไม่มีปุ่มให้กด ก็ไม่มีทางเรียกฟังก์ชันนี้ได้อีกจากหน้าจอผลลัพธ์นั้นอยู่แล้ว

## สรุปขอบเขตการแก้ไขที่อนุญาต (Checklist)

- [ ] `#screen-result` — จัดลำดับ DOM ใหม่: ย้าย `#result-status-bar` ขึ้นบนสุด, ปรับระยะห่าง h1/h2 ด้านล่าง
- [ ] `handleWin(winnerId)` — เพิ่มเงื่อนไขเช็คคะแนนรวม ≥ 200 หลังบวกคะแนน, ตั้ง `game.matchOver`, แนบ `matchOver` ไปกับ event `endGame`
- [ ] ฝั่ง client ที่รับ event `endGame` — อ่านค่า `matchOver` แล้วส่งต่อให้ `showResult`
- [ ] `showResult(winnerId, score, ...)` — เพิ่มพารามิเตอร์/การรับค่า `matchOver`, สุ่มประโยค "จ้าวแห่ง Uno" 1 ใน 5 ประโยคเมื่อ `matchOver === true`, ซ่อน `#result-host-controls` เมื่อ `matchOver === true`
- [ ] **ห้ามแก้อย่างอื่นนอกเหนือจากนี้ทั้งสิ้น**

เมื่อแก้ไขเสร็จสมบูรณ์ ให้ทดสอบด้วยตนเองในใจ (dry run) ว่า:
1. เล่นจบตาปกติ (คะแนนรวมยังไม่ถึง 200) → หน้าจอผลลัพธ์เหมือนเดิมทุกอย่าง ยกเว้นตำแหน่งแถบสถานะที่ย้ายขึ้นบน, ปุ่มเล่นรอบใหม่ยังอยู่ (ฝั่ง host)
2. เล่นจนมีผู้เล่นคะแนนรวมถึง 200+ → ขึ้นข้อความ "จ้าวแห่ง Uno" แบบสุ่ม, ปุ่มเล่นรอบใหม่หายไปแม้เป็น host, เหลือปุ่มกลับหน้าหลักปุ่มเดียว
3. ผู้เล่นที่ไม่ใช่เจ้าของตายังคงกด action ใดๆ ไม่ได้เหมือนเดิม (ของเดิมถูกต้องอยู่แล้ว ไม่ต้องแก้)

ส่งไฟล์ `uno.html` ฉบับสมบูรณ์กลับมาเมื่อแก้ไขครบถ้วนตามรายการนี้
