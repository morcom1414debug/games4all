# PROMPT: แก้ปัญหาห้องออนไลน์ค้างในเกม PingPong ให้หายขาด

ฉันต้องการให้คุณตรวจสอบและแก้ไขระบบจัดการห้องออนไลน์ของเกม World Audio PingPong Championships ซึ่งใช้ Firebase Realtime Database สำหรับสร้างห้อง และ PeerJS สำหรับเล่นออนไลน์แบบ 1 ต่อ 1

**ปัญหาที่พบจริง**

ทุกครั้งที่เข้าสู่ล็อบบี้ออนไลน์ ยังคงพบห้องเก่าปรากฏอยู่เสมอ ได้แก่

"เข้าร่วมห้อง PingPong00005 สร้างโดย Long"

แม้เจ้าของห้องจะออกจากเกมไปแล้ว ห้องนี้ก็ยังคงแสดงอยู่

ต้องการแก้ไขปัญหานี้ให้ครอบคลุมทั้งห้องที่ค้างอยู่ในปัจจุบันและห้องที่อาจค้างในอนาคต

## 1. ไฟล์ที่แนบ

1. `ping-online(1).js` — ไฟล์หลักที่ต้องแก้ไข
2. `ping(3).html` — ใช้อ้างอิงเท่านั้น
3. `auth(2).js` — ใช้อ้างอิงเท่านั้น

อนุญาตให้แก้ไขเฉพาะ `ping-online(1).js` เท่านั้น

## 2. กฎเหล็ก — ต้องปฏิบัติอย่างเคร่งครัดที่สุด

1. แก้ไขเฉพาะระบบจัดการห้องค้าง ห้องหมดอายุ การตรวจสอบเจ้าของห้อง และการทำความสะอาดห้องออนไลน์เท่านั้น
2. ห้ามแก้ไขไฟล์ HTML และ auth.js โดยเด็ดขาด
3. ห้ามเปลี่ยนกฎกติกาการเล่นปิงปอง
4. ห้ามเปลี่ยนระบบการตีลูก การเคลื่อนที่ของลูก ความเร็วลูก หรือการคำนวณคะแนน
5. ห้ามเปลี่ยนระบบ PeerJS ที่ใช้รับส่งข้อมูลระหว่างผู้เล่น เว้นแต่ส่วนที่จำเป็นโดยตรงต่อการตรวจสอบการเชื่อมต่อและการจัดการห้องค้าง
6. ห้ามเปลี่ยนระบบ Web Audio API และไฟล์เสียงทั้งหมด
7. ห้ามเปลี่ยนระบบ Motion Sensor และการขออนุญาตเซ็นเซอร์บน iOS Safari
8. ห้ามเปลี่ยนระบบ Screen Reader, aria-live, การประกาศเสียง และการจัดการ Focus
9. ห้ามเปลี่ยนระบบคีย์บอร์ดหรือปุ่มควบคุม
10. ห้ามเปลี่ยนระบบล็อกอิน สมัครสมาชิก หรือบันทึกสถิติ
11. ห้ามเปลี่ยน Firebase Config, GAME_ID หรือโครงสร้างบัญชีผู้เล่น
12. ห้ามเปลี่ยนระบบสร้างหมายเลขห้อง PingPong00001, PingPong00002 และหมายเลขถัดไป
13. ห้ามเปลี่ยนระบบเล่นออนไลน์ 1 ต่อ 1 ให้เป็นรูปแบบอื่น
14. ห้าม Refactor โค้ดส่วนที่ไม่เกี่ยวข้อง
15. ห้ามลบฟังก์ชันเดิมที่ยังจำเป็นต่อการทำงาน
16. ห้ามเปลี่ยนชื่อฟังก์ชัน ตัวแปร หรือโครงสร้างที่ HTML เรียกใช้งานโดยไม่จำเป็น
17. ต้องรักษาการทำงานเดิมทั้งหมดที่ไม่เกี่ยวข้องกับปัญหาห้องค้าง
18. ห้ามแก้ปัญหาด้วยการซ่อนรายการห้องอย่างเดียว โดยไม่จัดการข้อมูลค้างใน Firebase
19. ห้ามลบห้องที่ยังมีเจ้าของออนไลน์และกำลังใช้งานจริง
20. ต้องตรวจสอบโค้ดเดิมทั้งไฟล์ก่อนแก้ไข และแก้เฉพาะจุดที่จำเป็น

## 3. สิ่งที่ต้องแก้ไข

### 3.1 แก้ปัญหาห้องค้างที่มีอยู่ในปัจจุบัน

ตรวจสอบโครงสร้าง Firebase ที่ใช้เก็บห้องออนไลน์

โดยเฉพาะห้อง `PingPong00005` ซึ่งสร้างโดย `Long`

เมื่อเข้าสู่ล็อบบี้ออนไลน์ ต้องตรวจสอบว่าห้องที่มีสถานะ waiting ยังมีเจ้าของห้องเชื่อมต่ออยู่จริงหรือไม่

หากยืนยันได้ว่าห้องหมดอายุหรือเจ้าของไม่ได้เชื่อมต่อแล้ว ให้ลบข้อมูลห้องนั้นออกจาก Firebase Realtime Database โดยอัตโนมัติ

ต้องไม่ลบห้องจากการคาดเดาเพียงอย่างเดียว

หากไม่สามารถตรวจสอบสถานะได้แน่นอน ต้องใช้เกณฑ์หมดอายุที่ปลอดภัย

ห้ามลบข้อมูลผู้เล่น สถิติ หรือบัญชี Firebase

### 3.2 ปรับระบบ onDisconnect()

ตรวจสอบการใช้งาน `onDisconnect()` เดิมทั้งหมด

แก้ไขให้ระบบตรวจพบเมื่อเจ้าของห้องขาดการเชื่อมต่อกับ Firebase

ต้องรองรับกรณีต่อไปนี้:

- เจ้าของห้องกดออกจากห้องตามปกติ
- เจ้าของห้องปิดแท็บ
- เจ้าของห้องปิดเบราว์เซอร์
- เจ้าของห้องอินเทอร์เน็ตหลุด
- เจ้าของห้องปิดแอปบนมือถือ
- เจ้าของห้อง Refresh หน้าเว็บ
- เจ้าของห้องสลับแอปบน iOS Safari แล้วกลับมา

ต้องใช้ Firebase Presence และ onDisconnect อย่างถูกต้อง

ห้ามอาศัย `beforeunload` หรือ `pagehide` เพียงอย่างเดียว เพราะไม่รับประกันการทำงานบนมือถือ

ต้องลงทะเบียน onDisconnect ก่อนประกาศสถานะออนไลน์ตามแนวทางที่ปลอดภัย และจัดการกรณีลงทะเบียนไม่สำเร็จด้วย

### 3.3 เพิ่มระบบ Heartbeat และตรวจสอบห้องหมดอายุ

เพิ่มระบบยืนยันว่าเจ้าของห้องยังออนไลน์จริง

ใช้ข้อมูลเวลาจาก Firebase Server เท่าที่เหมาะสม เพื่อลดปัญหานาฬิกาของอุปกรณ์แต่ละเครื่องไม่ตรงกัน

ต้องมีการตรวจสอบสถานะการเชื่อมต่อควบคู่กับ Heartbeat

หากเจ้าของห้องขาดการเชื่อมต่อเกินระยะเวลาที่กำหนด ให้จัดการห้องหมดอายุโดยอัตโนมัติ

ข้อกำหนดสำคัญ:

- ห้ามใช้ Heartbeat ที่ถี่จนเกิดภาระ Firebase โดยไม่จำเป็น
- ต้องหยุด Heartbeat เมื่อออกจากห้อง
- ต้องไม่สร้าง Timer ซ้ำเมื่อเข้าล็อบบี้หลายครั้ง
- ต้องรองรับ Safari iOS ที่อาจหยุด JavaScript ชั่วคราวเมื่อแอปอยู่เบื้องหลัง
- ห้ามถือว่าเจ้าของห้องออฟไลน์จาก Heartbeat ที่ล่าช้าเพียงครั้งเดียว

### 3.4 เพิ่มระบบ Auto Cleanup

เมื่อผู้เล่นเข้าสู่ล็อบบี้ออนไลน์ ให้ระบบตรวจสอบรายการห้องที่มีอยู่ใน Firebase

ห้องที่ยืนยันได้ว่าหมดอายุแล้วต้องถูกลบออกจากฐานข้อมูล

ห้องที่ยังใช้งานจริงต้องไม่ถูกลบ

ต้องป้องกัน Race Condition เช่น เจ้าของห้องกลับมาเชื่อมต่อใหม่ระหว่างที่ระบบกำลังตรวจสอบ

ใช้ Firebase Transaction หรือวิธีตรวจสอบแบบ Atomic ที่เหมาะสม เพื่อไม่ให้การลบข้อมูลจากสถานะเก่าไปกระทบห้องที่กลับมาใช้งานแล้ว

ต้องรองรับห้องหลายห้องที่เปิดพร้อมกัน โดยไม่ลบผิดห้อง

การ Cleanup ต้องไม่กระทบการแข่งขันที่กำลังดำเนินอยู่ และต้องไม่ทำให้ระบบ Reconnect เดิมเสียหาย

### 3.5 ป้องกันห้องผีในรายการเข้าร่วม

แก้ระบบแสดงรายการห้องออนไลน์ให้แสดงเฉพาะห้องที่:

- มีสถานะ waiting
- มีเจ้าของห้องที่ยังออนไลน์ตามเกณฑ์ที่ตรวจสอบได้
- ยังไม่หมดอายุ
- ยังเปิดรับผู้เล่นคนที่สองจริง

หากพบห้องค้าง ต้องไม่แสดงปุ่มเข้าร่วมห้องนั้น

หากผู้เล่นกดเข้าร่วมในจังหวะที่ห้องหมดอายุพอดี ต้องแจ้งอย่างเหมาะสมและกลับไปแสดงรายการห้องโดยไม่ทำให้เกมค้าง

### 3.6 รักษาระบบ Refresh และ Reconnect

ระบบเดิมมีการกู้คืนห้องเมื่อ Refresh หน้าเว็บ

ต้องรักษาความสามารถนี้ไว้

ห้ามแก้ไขจนผู้เล่น Refresh แล้วห้องถูกลบทันที

ต้องกำหนดช่วงเวลาผ่อนผันให้เจ้าของห้องสามารถกลับมาเชื่อมต่อได้อย่างปลอดภัย

หากเจ้าของห้องกลับมาภายในเวลาที่กำหนด ต้องสามารถกู้คืนห้องเดิมได้

หากหมดระยะเวลาผ่อนผันและยืนยันว่าไม่มีเจ้าของเชื่อมต่อแล้ว จึงดำเนินการลบห้อง

ต้องแยกกรณีห้อง waiting ออกจากการแข่งขันที่กำลังเล่นอยู่ เพื่อไม่ให้ระบบ Cleanup ไปทำลายระบบกลับเข้าแข่งขันเดิม

## 4. ข้อกำหนดด้านความปลอดภัย

1. ห้ามให้ผู้เล่นทั่วไปลบห้องที่ยังมีเจ้าของใช้งานอยู่
2. ห้ามลบห้องโดยอาศัยเพียงเวลาที่ผ่านไป หากยังมีหลักฐานว่าเจ้าของออนไลน์อยู่
3. ห้ามให้การเชื่อมต่อจากแท็บเก่าลบห้องที่ถูกสร้างหรือกู้คืนโดยเซสชันใหม่
4. ต้องใช้ Room ID และ Session ID หรือข้อมูลระบุตัวตนการเชื่อมต่อที่เหมาะสม
5. ตรวจสอบสิทธิ์และเงื่อนไขการลบตามความสามารถของ Firebase Realtime Database Rules เดิม
6. หากการรับประกันความปลอดภัยต้องแก้ Firebase Security Rules หรือใช้ Cloud Functions ซึ่งอยู่นอกขอบเขตไฟล์ที่อนุญาต ห้ามแอบเปลี่ยน ให้แจ้งข้อจำกัดอย่างชัดเจน
7. ห้ามอ้างว่าระบบ Cleanup ฝั่ง Browser สามารถลบห้องได้ตลอดเวลาแม้ไม่มีผู้ใช้เปิดเว็บไซต์ เพราะ JavaScript ฝั่ง Browser ไม่สามารถทำงานได้เมื่อไม่มี Client ทำงานอยู่

## 5. การทดสอบที่ต้องผ่าน

ตรวจสอบตรรกะของโค้ดให้ครอบคลุมอย่างน้อยดังนี้

1. สร้างห้องใหม่แล้วห้องปรากฏตามปกติ
2. ผู้เล่นอีกคนเห็นห้องและเข้าร่วมได้
3. เจ้าของกดออกจากห้อง ห้องถูกจัดการอย่างถูกต้อง
4. เจ้าของปิดแท็บโดยไม่กดออก ระบบตรวจพบการขาดการเชื่อมต่อ
5. เจ้าของอินเทอร์เน็ตหลุด ห้องถูกจัดการเมื่อหมดระยะเวลาที่ปลอดภัย
6. เจ้าของ Refresh แล้วกลับเข้าห้องเดิมได้ตามเงื่อนไข
7. เจ้าของกลับมาหลังห้องหมดอายุแล้ว ไม่สามารถกู้คืนห้องที่ถูกลบไปแล้ว
8. ห้องเก่า PingPong00005 ที่ยืนยันว่าค้างถูกลบออกจาก Firebase
9. ห้องของผู้เล่นอื่นที่ยังออนไลน์ไม่ถูกลบ
10. เปิดล็อบบี้ซ้ำหลายครั้งแล้วไม่มี Listener หรือ Timer ซ้อนกัน
11. ผู้เล่นสองคนแข่งขันกันตามปกติ
12. การหลุดและกลับเข้าแข่งขันยังทำงานตามระบบเดิม
13. ไม่เกิดข้อผิดพลาดเมื่อมีผู้เล่นหลายคนตรวจสอบห้องค้างพร้อมกัน
14. การทำงานบน Windows, Android และ iOS Safari ไม่ได้รับผลกระทบ

หากไม่มีสภาพแวดล้อมสำหรับทดสอบ Firebase หรือ Browser จริง ต้องแยกผลการตรวจสอบโค้ดออกจากผลการทดสอบจริงอย่างชัดเจน ห้ามอ้างว่าทดสอบผ่านแล้วโดยไม่ได้ทดสอบ

## 6. กฎเหล็กในการส่งไฟล์กลับ

**สำคัญที่สุด: ต้องส่งไฟล์ JavaScript ฉบับเต็มเท่านั้น**

1. ส่งกลับเป็นไฟล์ `ping-online.js` ที่แก้ไขเสร็จสมบูรณ์
2. ต้องมีโค้ดครบทุกบรรทัดตั้งแต่ต้นจนจบ
3. ห้ามตัดทอนโค้ดเด็ดขาด
4. ห้ามใช้ `...` แทนโค้ด
5. ห้ามเขียนว่า "โค้ดส่วนอื่นเหมือนเดิม"
6. ห้ามส่งเฉพาะส่วนที่แก้ไข
7. ห้ามส่ง Diff หรือ Patch แทนไฟล์เต็ม
8. ห้ามลบฟังก์ชันที่ไม่เกี่ยวข้อง
9. ห้ามสร้างไฟล์ใหม่ที่ต้องพึ่งพาเพิ่มเติม
10. ห้ามเปลี่ยนชื่อไฟล์ที่ HTML เรียกใช้งาน
11. ต้องรักษา Import และ Export เดิมทั้งหมดที่จำเป็น
12. ต้องตรวจสอบ Syntax Error ก่อนส่ง
13. ต้องตรวจสอบว่าทุกฟังก์ชันที่ถูกเรียกยังมีอยู่ครบ
14. ต้องส่งไฟล์ให้ดาวน์โหลดได้จริง
15. ห้ามส่งไฟล์ที่มีเพียงคำอธิบายหรือโค้ดบางส่วน

หลังจากแก้ไขเสร็จ ให้สรุปสั้น ๆ ว่า:

- แก้ไขฟังก์ชันใดบ้าง
- ระบบจัดการห้องค้างทำงานอย่างไร
- ห้อง PingPong00005 จะถูกจัดการด้วยเงื่อนไขใด
- มีข้อจำกัดใดที่ต้องตั้งค่าเพิ่มเติมใน Firebase หรือไม่

**เป้าหมายสุดท้าย**

แก้ปัญหาห้องออนไลน์ค้างให้ได้อย่างปลอดภัยทั้งปัจจุบันและอนาคต โดยไม่กระทบระบบเกมปิงปองออนไลน์ที่ทำงานได้ดีอยู่แล้ว

ต้องแก้เฉพาะเรื่องนี้เรื่องเดียวเท่านั้น และส่งไฟล์ `ping-online.js` กลับมาแบบครบถ้วน 100% ห้ามตัดทอนใด ๆ เด็ดขาด
