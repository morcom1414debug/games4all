# งาน: สร้างเกม DOMINO Online โดยใช้เกม UNO ต้นแบบเป็นแม่แบบหลักของระบบ

ฉันจะแนบไฟล์เกม UNO ต้นแบบให้คุณ ซึ่งอาจประกอบด้วยไฟล์ HTML, CSS และ JavaScript

รวมถึงไฟล์ Prompt สำหรับกำหนดกติกาเกม DOMINO

งานของคุณคือสร้างเกม **DOMINO Online** ใหม่ โดยใช้เกม UNO ที่แนบมาเป็น **Reference Architecture และแม่แบบหลักของระบบ**

# การ Mapping เสียงจาก UNO ไป DOMINO

ให้ AI วิเคราะห์ความเหมาะสมของเสียงเดิมกับ Event ใหม่

ตัวอย่างแนวคิด:

* เสียงสร้างห้อง → ใช้เสียงเดิมที่ UNO ใช้
* เสียงเลือกปุ่ม → ใช้ select เดิม
* เสียงเริ่มเกม → ใช้ start เดิม
* เพลงพื้นหลัง → ใช้ bgm เดิม
* เสียงถึงรอบ → ใช้ turn เดิม
* เสียงจั่ว → ใช้ jua เดิมหรือเสียงเดิมที่เหมาะสม
* เสียงชนะ → ใช้ win เดิม
* เสียง Event พิเศษ → ใช้เสียง special เดิมที่เหมาะสม
* เสียงประกาศ DOMINO → ใช้ไฟล์ uno เดิมได้ หากเหมาะสม หรือ Mapping ให้เป็น DOMINO Event โดยไม่ต้องเปลี่ยนไฟล์

# Audio Queue

ต้องรักษาแนวคิด Audio Queue จาก UNO ต้นแบบ

เสียงที่เกิดติดกันต้องไม่ชนกันแบบควบคุมไม่ได้

ตัวอย่าง:

ผู้เล่นวางโดมิโน่พิเศษ

อาจเกิดลำดับ:

1. เสียงเลือก
2. เสียง Action
3. เสียง Effect
4. เสียงเปลี่ยน Turn

ต้องจัดลำดับตามความเหมาะสม

ห้ามให้เสียงสำคัญตัดกันมั่วจนผู้เล่นตาบอดไม่สามารถเข้าใจสถานการณ์

# BGM

ต้องใช้แนวทางเดียวกับ UNO

Background Music:

* เล่นแบบ Loop
* ไม่สร้าง BGM ซ้อนหลายตัว
* หยุดเมื่อออกจากเกมหรือออกจากห้องตาม Flow ที่เหมาะสม
* ต้องไม่ทำให้ BGM ซ้อนกันหลังเปลี่ยนหน้า
* ต้องจัดการ AudioContext ให้ทำงานได้บน Browser และ Mobile Browser

# Multiplayer Sound

หาก UNO ต้นแบบมีระบบ Broadcast Sound ผ่าน Peer.js:

ให้ใช้แนวคิดเดียวกัน

Game Logic ต้องมาจาก Host

# การจั่ว DOMINO ต้องใช้ระบบเสียงเดิม

เกม DOMINO ไม่มีปุ่มจั่ว

ดังนั้นเมื่อผู้เล่นไม่มีโดมิโน่ที่วางได้ ระบบต้องจั่วอัตโนมัติ

## สำคัญมาก

ให้นำเสียงหรือจังหวะที่ UNO ต้นแบบใช้กับการจั่วการ์ดมาปรับใช้กับ:

# การจั่วโดมิโน่อัตโนมัติ

ผู้เล่นไม่ต้องกดปุ่ม

แต่เมื่อ Game Logic ตรวจพบว่าไม่มีโดมิโน่ที่เล่นได้:

1. เริ่มกระบวนการ Auto Draw
2. เล่นเสียงจั่วตามจังหวะที่เหมาะสม
3. แสดง Animation การจั่ว
4. เพิ่มโดมิโน่ทีละตัว
5. ตรวจสอบว่ามีโดมิโน่ที่วางได้หรือไม่
6. หากยังไม่มี ให้จั่วต่อ
7. หยุดเมื่อพบตัวที่เล่นได้ หรือ Deck หมด

---

# จังหวะเสียงตอน Auto Draw

ให้ใช้ Audio Queue และ Timing ที่เหมาะสม

ตัวอย่าง:

จั่วตัวที่ 1

เสียง → Animation → เพิ่มข้อมูล

ตรวจสอบ

หากยังเล่นไม่ได้

จั่วตัวที่ 2

เสียง → Animation → เพิ่มข้อมูล

ทำต่อไปตาม Logic

ต้องไม่ทำให้เสียง 5 ครั้งดังพร้อมกัน

# Visual Animation สำหรับการจั่ว

ให้นำแนวคิด Animation การจั่วการ์ดของ UNO มาใช้กับ DOMINO

แต่เปลี่ยนรูปลักษณ์จาก:

UNO Card

เป็น:

DOMINO Tile

ตัว Animation ต้อง:

* เริ่มจากกองจั่ว
* เคลื่อนที่ไปยังมือผู้เล่น
* หรือเคลื่อนที่ไปยังตัวละครของผู้เล่นคนอื่น
* ใช้ aria-hidden="true" สำหรับ Animation ที่เป็นเพียง Visual
* ไม่สร้างข้อมูลสำคัญซ้ำให้ Screen Reader อ่าน

# Visual Animation ตอนวาง DOMINO

ให้นำแนวคิด Animation การวางการ์ดของ UNO มาใช้

* Domino Tile
* การเคลื่อนจากมือผู้เล่น
* ไปยังปลายซ้ายหรือปลายขวา
* มี Motion ที่ดูเป็นธรรมชาติ
* มี Effect เล็กน้อยเมื่อวางสำเร็จ

* Scale

# prefers-reduced-motion

ต้องรองรับ:

prefers-reduced-motion: reduce

หากผู้ใช้ตั้งค่าลด Animation:

* ลดหรือปิด Animation ที่ไม่จำเป็น
* Game Logic ต้องทำงานเหมือนเดิม
* Accessibility ต้องไม่เปลี่ยน
* ไม่ใช้ Animation เป็นข้อมูลสำคัญ
