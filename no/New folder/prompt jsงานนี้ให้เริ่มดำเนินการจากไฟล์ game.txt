## ขอบเขตที่อนุญาตให้แก้ไขในไฟล์นี้

อนุญาตให้ปรับเฉพาะส่วนที่เกี่ยวข้องกับ Visual Animation ได้แก่

* `visualAnimThrowCoin()`
* `visualAnimDealCard()`
* `visualAnimTakeCard()`
* `triggerVisualsFromAnnounce()`

และอนุญาตให้เพิ่มตัวแปรหรือฟังก์ชันช่วยเหลือใหม่ได้ เฉพาะเมื่อใช้สำหรับ Visual Animation เท่านั้น

ฟังก์ชันใหม่ทั้งหมดต้อง:

* ไม่แก้ Game State
* ไม่เขียน Firebase
* ไม่ส่ง PeerJS Message
* ไม่เปลี่ยน Turn
* ไม่เปลี่ยน Timer
* ไม่เรียก `announce()` เพื่อสร้างข้อความใหม่
* ไม่แก้ข้อความประกาศเดิม
* ไม่เปลี่ยน Focus
* ไม่เปลี่ยน DOM Accessibility เดิม
* Element Visual ที่สร้างเพิ่มชั่วคราวต้องใช้ `aria-hidden="true"`
* เมื่อ Animation จบ ต้องลบ Element Visual ชั่วคราวออก

ระบบ Trigger ต้องยังใช้ Event เดิมของเกม

ห้ามเปลี่ยนข้อความ Regex หรือข้อความประกาศเพื่อรองรับ Animation

ให้ Animation ทำงานเป็น Visual Layer เพิ่มเติมเท่านั้น

# ส่วนที่ 1 : ตอนผู้เล่นกด "ผ่าน" และจ่ายเหรียญ

ระบบเดิมทำงานถูกต้องอยู่แล้ว

ให้ปรับเฉพาะ `visualAnimThrowCoin()`

เมื่อมีการจ่ายเหรียญและจำนวนเหรียญบนไพ่เพิ่มขึ้น

ต้องทำให้เกิด Visual ดังนี้

1. เหรียญที่แสดงอยู่บนไพ่หรือ Badge เหรียญมุมขวาบน

เมื่อจำนวนเหรียญเปลี่ยน

* ขยายประมาณ 160%
* มี Glow สีทอง
* มีประกายแวววาวสั้น ๆ
* จากนั้นกลับสู่ขนาดปกติ
* ระยะเวลาประมาณ 0.3 ถึง 0.5 วินาที

2. ไพ่กลางโต๊ะ

เมื่อมีคนจ่ายเหรียญ

ให้ไพ่กลางโต๊ะ

* เอียงไปทางซ้ายเล็กน้อย
* เอียงไปทางขวาเล็กน้อย
* กลับมาตรง

ให้ความรู้สึกเหมือนไพ่ถูกเหรียญกระแทก

Animation ต้องสั้นและไม่กระทบการเล่น

ผลลัพธ์ที่ต้องการคือ ผู้เล่นมองเห็นแล้วเข้าใจทันทีว่า

"มีเหรียญถูกวางเพิ่มบนไพ่"

ห้ามเปลี่ยน Logic การจ่ายเหรียญเดิม

# ส่วนที่ 2 : ตอนเปิดไพ่ใบใหม่จากกองไพ่

ปรับเฉพาะ `visualAnimDealCard()`

ปัจจุบันระบบเปลี่ยนไพ่ทำงานถูกต้องแล้ว

ห้ามแก้ไขการเปิดไพ่จริง
ห้ามแก้ไข Deck

ห้ามแก้ไข setTimeout ของ Logic เกม

ให้ปรับเฉพาะภาพที่ผู้เล่นมองเห็น

ต้องทำให้รู้สึกว่ากำลังเปิดไพ่จริงจากกองไพ่ด้านซ้าย

ลำดับ Visual ที่ต้องการ

1. ไพ่ Visual ถูกดึงออกจากตำแหน่งกองไพ่
2. เคลื่อนที่จากกองไพ่ไปยังตำแหน่งไพ่กลางโต๊ะ
3. ระหว่างเคลื่อนที่มีการพลิกหน้าไพ่
4. เมื่อถึงปลายทางให้เด้งเล็กน้อย
5. ไพ่ใหม่ปรากฏชัดเจนที่ตำแหน่งกลางโต๊ะ

ใช้เวลาประมาณ 0.6 ถึง 0.8 วินาที

ต้องดูเป็นธรรมชาติ

สำคัญ:

Animation ต้องทำงานคู่ขนานกับระบบเดิม

# ส่วนที่ 3 : ตอนผู้เล่นรับไพ่

ปรับเฉพาะ `visualAnimTakeCard()`

ห้ามแก้ Logic การรับไพ่

ให้เพิ่มเฉพาะ Visual

## ไพ่บนโต๊ะ

ก่อนออกจากโต๊ะ

* ขยายเล็กน้อย
* เอียงเล็กน้อย
* จากนั้นเคลื่อนที่อย่างชัดเจนไปยังตำแหน่งผู้เล่นที่รับไพ่

ต้องไม่หายวับทันที

ต้องเห็นเส้นทางการเคลื่อนที่

หากเป็นผู้เล่นเครื่องปัจจุบัน ให้บินไปยัง HUD หรือพื้นที่ผู้เล่นเครื่องปัจจุบัน

หากเป็นผู้เล่นอื่น ให้บินไปยัง Visual Avatar ของผู้เล่นคนนั้นตามระบบเดิม

## เหรียญบนไพ่

เมื่อผู้เล่นรับไพ่

เหรียญทั้งหมดบนไพ่ต้องมี Visual บินไปยังผู้เล่น

* ใช้วิถีโค้งเล็กน้อย
* มีการกระจายตัวเล็กน้อย
* ดูมีชีวิตมากขึ้น
* แต่ยังรวดเร็ว
* ไม่เกินประมาณ 0.6 วินาที

ต้องเป็น Visual Element เท่านั้น

จำนวนเหรียญใน Game State ต้องไม่ถูกแก้ไขโดย Animation

ผลลัพธ์คือ

ผู้เล่นมองเห็นแล้วเข้าใจทันทีว่า

"ผู้เล่นคนนี้ได้รับทั้งไพ่และเหรียญ"

# ส่วนที่ 4 : สถานะผู้เล่นของเครื่องปัจจุบัน

ใน `game(6).js` อนุญาตให้เพิ่ม Visual Trigger สำหรับตรวจจับการเพิ่มขึ้นของจำนวนเหรียญของผู้เล่นเครื่องปัจจุบัน

แต่ห้ามเปลี่ยน Logic การ Render สถานะเดิม

ห้ามเปลี่ยน `ariaLabelText`

ห้ามเปลี่ยนข้อความสำหรับ Screen Reader

ห้ามเปลี่ยนโครงสร้าง Accessibility เดิม

ห้ามเปลี่ยน Focus

เมื่อจำนวนเหรียญของผู้เล่นเครื่องปัจจุบันเพิ่มขึ้น

ให้ Trigger Animation กับ Element Visual ที่มีอยู่แล้ว เช่น `.my-status-coin`

Animation ที่ CSS จะจัดการต้องให้ผลดังนี้

* ขยายประมาณ 180%
* Glow สีทอง
* ประกายแวววาว
* เด้ง 1 ถึง 2 ครั้ง
* กลับสู่ปกติ
* ประมาณ 0.5 วินาที

ต้อง Trigger เฉพาะเมื่อจำนวนเหรียญเพิ่มขึ้นจริง

ห้าม Trigger ทุกครั้งที่ UI Render

ต้องเก็บค่าเดิมเพื่อเปรียบเทียบเฉพาะ Visual State เท่านั้น

Visual State ต้องไม่เกี่ยวข้องกับ Game State
