# วิธีการเล่นและกฎกติกา

## เกมผจญภัย 80 ช่อง สำหรับ Games4All

> เอกสารฉบับนี้เป็นข้อกำหนดกติกาหลักของเกม ใช้เป็นเอกสารอ้างอิงในการพัฒนาเกมจริง
> เกมนี้เป็นเกมกระดานทอยลูกเต๋าและผจญภัย ไม่ใช่เกมไพ่ และไม่มีระบบไพ่ใด ๆ

---

# 1. แนวคิดของเกม

เกมเป็นเกมกระดานผจญภัยแบบ Multiplayer ผู้เล่นแต่ละคนรับบทเป็นสัตว์น่ารักที่ระบบสุ่มให้โดยอัตโนมัติ แล้วแข่งขันกันเดินทางจากช่องเริ่มต้นไปยังช่อง FINISH

กระดานมีทั้งหมด **80 ช่อง**

* START = ช่อง 1
* FINISH = ช่อง 80
* ผู้เล่นทอยลูกเต๋าเพื่อเดิน
* ระหว่างทางมีช่องเหตุการณ์พิเศษแบบสุ่ม
* เหตุการณ์แต่ละเกมจะถูกสุ่มใหม่
* ผู้เล่นสามารถเก็บกุญแจและเกราะศักดิ์สิทธิ์ไว้ใช้ในภายหลัง
* ผู้เล่นคนแรกที่เข้าสู่ช่อง 80 แบบตรงจังหวะตามกติกาเป็นผู้ชนะทันที

เกมเน้นความสนุกจากการสุ่ม เหตุการณ์ และการเดินทาง โดยผู้เล่นไม่สามารถจำตำแหน่งช่องพิเศษจากเกมก่อนหน้าได้

---

# 2. จำนวนผู้เล่น

* รองรับผู้เล่นสูงสุด 6 คนต่อห้อง
* ต้องมีผู้เล่นอย่างน้อย 2 คนจึงเริ่มเกมได้
* สามารถเพิ่ม Bot ได้ตามระบบ Lobby
* Bot นับรวมอยู่ในจำนวนผู้เล่นสูงสุด 6 คน
* ผู้เล่นจริงและ Bot ใช้ช่องสถานะและระบบเกมเดียวกัน

---

# 3. ชื่อผู้เล่น

ก่อนสร้างหรือเข้าห้อง ผู้เล่นต้องกรอกชื่อเล่น

ชื่อเล่นต้องถูกนำไปใช้เหมือนระบบเกม Multiplayer รุ่นปัจจุบัน เช่น

* Lobby
* สถานะผู้เล่น
* ตัวละครบนกระดาน
* การประกาศด้วย Screen Reader
* หน้าสรุปผล

ชื่อผู้เล่นต้องไม่ทำให้ระบบ HTML หรือ JavaScript เสียหาย และต้อง escape ข้อมูลที่นำมาแสดงผลอย่างเหมาะสม

---

# 4. สัตว์ประจำตัว

ผู้เล่น **ไม่ต้องเลือกสัตว์เอง**

เมื่อเข้าร่วมห้อง ระบบจะสุ่มสัตว์น่ารักให้โดยอัตโนมัติ

ตัวอย่างกลุ่มสัตว์:

* 🦊 จิ้งจอก
* 🐼 แพนด้า
* 🐰 กระต่าย
* 🐨 โคอาลา
* 🐯 เสือ
* 🦁 สิงโต
* 🐸 กบ
* 🐵 ลิง
* 🐧 เพนกวิน
* 🐻 หมี
* 🦝 แร็กคูน
* 🦄 ยูนิคอร์น
* 🐹 แฮมสเตอร์
* 🐱 แมว
* 🐶 สุนัข
* 🐾 แพนด้าแดง

ควรมีสัตว์ประมาณ 12–20 แบบ

ภายในห้องเดียวกันควรหลีกเลี่ยงการสุ่มสัตว์ซ้ำกัน หากจำนวนสัตว์ที่มีเพียงพอ

การสุ่มสัตว์ต้องเกิดจาก Host และ synchronize ไปยังผู้เล่นทุกคน

ผู้เล่นทุกอุปกรณ์ต้องเห็นคู่เดียวกัน เช่น

> 🐰 น้องฟ้า

สัตว์เป็นตัวละครที่แสดงบนกระดานและใช้ใน Player Status Card

---

# 5. รูปแบบกระดาน

กระดานมี 80 ช่อง

สามารถออกแบบการแสดงผลเป็นตาราง 8 แถว × 10 ช่องแบบเดินสลับทิศทางได้ แต่ในเชิงกติกาให้ถือว่าเส้นทางเป็นเส้นเดียว:

> 1 → 2 → 3 → ... → 79 → 80

Screen Reader ไม่จำเป็นต้องเข้าใจแถวและคอลัมน์

ควรประกาศตำแหน่งเป็น:

> ช่อง 27 จาก 80

ไม่ควรบังคับให้ผู้ใช้ Screen Reader ต้องตีความว่าอยู่แถวใดหรือคอลัมน์ใด

---

# 6. การเริ่มเกม

เมื่อมีผู้เล่นอย่างน้อย 2 คน Host สามารถกดเริ่มเกม

เมื่อเริ่มเกม:

1. Host สร้าง Seed/ข้อมูลสุ่มของเกม
2. Host สร้างตำแหน่งช่องพิเศษทั้งหมด
3. Host สร้างค่าผลของช่องพิเศษทั้งหมด
4. Host สุ่มสัตว์ของผู้เล่น
5. Host สร้างสถานะเริ่มต้นของผู้เล่น
6. ข้อมูลทั้งหมดถูก synchronize ไปยัง Client
7. ทุกอุปกรณ์ต้องใช้ข้อมูลชุดเดียวกัน
8. จึงเริ่มการแข่งขัน

**ห้ามให้ Client แต่ละเครื่องสุ่มกระดานเอง**

เกมหนึ่งเกมต้องมี layout เดียวกันสำหรับทุกคน

---

# 7. ตำแหน่งเริ่มต้น

ผู้เล่นทุกคนเริ่มที่:

> ช่อง 1

ช่อง 1 เป็น START

START ควรมีภาพหรือธีม เช่น

* 🏕️ จุดพักแรม
* 🔥 กองไฟ
* 🚩 ธงเริ่มต้น

START ไม่ควรเป็นช่องเหตุการณ์พิเศษอื่น

---

# 8. การทอยลูกเต๋า

ในแต่ละเทิร์น ผู้เล่นปัจจุบันมีสิทธิ์กด:

> ทอยลูกเต๋า

การทำงาน:

1. ตรวจสอบว่าเป็นเทิร์นของผู้เล่นหรือไม่
2. ผู้เล่นกดปุ่ม
3. ปุ่มถูกป้องกันการกดซ้ำ
4. สุ่มแต้มลูกเต๋า 1–6 โดย Host เป็นผู้ตัดสินผล
5. แสดงลูกเต๋า
6. ประกาศผลด้วย Screen Reader
7. ตัวละครเดินตามจำนวนช่อง
8. ตรวจสอบช่องปลายทาง
9. ประมวลผลเหตุการณ์
10. เปลี่ยนไปยังผู้เล่นคนถัดไป

ตัวอย่าง:

> คุณทอยได้ 5

จากนั้น:

> คุณเดินจากช่อง 27 ไปช่อง 32

ไม่ควรประกาศทุกช่องระหว่าง Animation เช่น

> ช่อง 28
> ช่อง 29
> ช่อง 30...

เพราะจะทำให้ Screen Reader พูดรบกวนและทำให้เกมใช้งานยาก

---

# 9. Animation การเดิน

ตัวละครต้องแสดงการเดินทีละช่องแบบมองเห็นได้

ตัวอย่าง:

27 → 28 → 29 → 30 → 31 → 32

แต่ Screen Reader ให้ประกาศเป็นข้อความรวมครั้งเดียว:

> น้องฟ้าเดินจากช่อง 27 ไปช่อง 32

การเคลื่อนไหวควรให้ความรู้สึกเหมือนตัวละครกำลังเดินผจญภัย

สามารถนำแนวคิด Animation ของเกม Snakes & Ladders มาใช้ต่อยอด เช่น

* กระโดดเล็กน้อย
* เด้ง
* เดิน
* ขยาย/ย่อ
* เอฟเฟกต์เคลื่อนที่

แต่ต้องไม่ทำให้ Accessibility เสีย

---

# 10. กรณีทอยเกินช่อง 80

ผู้เล่นต้องไม่สามารถหลุดออกจากกระดาน

หากแต้มทำให้เดินเกินช่อง 80 ให้ใช้ระบบ **Bounce Back**

ตัวอย่าง:

ผู้เล่นอยู่ช่อง 78 และทอยได้ 5

การเดินจะเป็น:

78 → 79 → 80 → 79 → 78 → 77

ดังนั้นจะจบที่:

> ช่อง 77

หลักสำคัญ:

* ช่อง 80 ต้องลงแบบตรงจังหวะจึงจะชนะ
* การเดินเกิน 80 ไม่ถือว่าชนะ
* ตัวละครต้องยังอยู่ในช่วง 1–80
* Algorithm ต้องเป็น deterministic และเหมือนกันทุกอุปกรณ์

---

# 11. ช่องพิเศษทั้งหมด

ในแต่ละเกมให้สุ่มช่องพิเศษใหม่

จำนวนพื้นฐาน:

| ประเภท                |        จำนวน |
| --------------------- | -----------: |
| 📦 กล่องสมบัติ        |            8 |
| 🚀 ช่องพุ่งไปข้างหน้า |            6 |
| 🕳️ กับดัก            |            7 |
| 🌊 กระแสน้ำ           |            5 |
| 👻 ผี                 |            5 |
| 🌀 วาร์ป              |            4 |
| 🔑 กุญแจ              |            6 |
| 🚪 ประตู              |            6 |
| ช่องปกติ              | ส่วนที่เหลือ |

รวมช่องพิเศษ 47 ช่อง

จาก 80 ช่อง จะมีช่องปกติประมาณ 33 ช่อง

---

# 12. กฎการสุ่มช่องพิเศษ

ตำแหน่งพิเศษต้องถูกสุ่มใหม่ทุกเกม

ข้อกำหนด:

* ห้ามใช้ตำแหน่งตายตัว
* ห้ามให้ Client สุ่มเอง
* Host เป็นผู้สร้าง configuration
* Client รับ configuration จาก Host
* ตำแหน่งพิเศษต้องไม่ซ้ำกัน
* ช่อง 1 และช่อง 80 ไม่ใช้เป็นช่องพิเศษ
* ต้องไม่มีช่องหนึ่งมี Special Type มากกว่า 1 ประเภท
* ต้องตรวจสอบ Constraint หลังสุ่ม
* หากสุ่มไม่ผ่าน Constraint ให้สุ่มใหม่
* ต้องเก็บข้อมูลผลของ Special แต่ละช่องไว้ใน Game State

---

# 13. 📦 กล่องสมบัติ

มีทั้งหมด 8 ช่อง

เมื่อผู้เล่นลงบนกล่องสมบัติ:

> ผู้เล่นได้รับเกราะศักดิ์สิทธิ์ 1 ชิ้น

ไม่ให้เหรียญ

ข้อความตัวอย่าง:

> ช่อง 32 เป็นกล่องสมบัติ คุณได้รับเกราะศักดิ์สิทธิ์ 1 ชิ้น

ควรมี Visual Effect เช่น

* กล่องเปิด
* ประกาย
* แสง
* เสียงรับสมบัติ

ผู้เล่นสามารถสะสมเกราะได้สูงสุด:

> 3 ชิ้น

หากมีเกราะครบ 3 ชิ้นแล้วและพบกล่องสมบัติอีกครั้ง:

> ไม่เพิ่มเกิน 3 ชิ้น

กรณีนี้ไม่ควรทำให้เกมค้างหรือเกิดการตัดสินใจเพิ่มเติม

---

# 14. 🛡️ เกราะศักดิ์สิทธิ์

เกราะศักดิ์สิทธิ์ใช้ป้องกันเหตุการณ์ร้ายที่สามารถป้องกันได้

เมื่อมีเหตุการณ์ที่ใช้เกราะป้องกันได้ และผู้เล่นมีเกราะ:

แสดงตัวเลือก:

> ใช้เกราะศักดิ์สิทธิ์ป้องกันหรือไม่?

มีสองตัวเลือก:

* ใช้เกราะ
* ไม่ใช้

หากใช้:

* ลดเกราะ 1 ชิ้น
* ยกเลิกผลเสียของเหตุการณ์
* ไม่ต้องเสียสิทธิ์เพิ่มเติมจากเหตุการณ์นั้น

หากไม่ใช้:

* ดำเนินผลเสียตามปกติ

เกราะไม่เกี่ยวข้องกับแต้มลูกเต๋าปกติ

---

# 15. 🚀 ช่องพุ่งไปข้างหน้า

มี 6 ช่อง

เมื่อผู้เล่นลงช่องนี้:

* สุ่มระยะเดินหน้า 2–6 ช่อง
* ผลสุ่มถูกกำหนดโดย Host
* แสดง Animation การพุ่ง
* ประกาศผล

ตัวอย่าง:

> ช่อง 24 เป็นช่องพุ่งไปข้างหน้า คุณพุ่งไปข้างหน้า 4 ช่อง

หากการพุ่งทำให้เกิน 80 ให้ใช้กฎ Bounce Back เช่นเดียวกับการทอยลูกเต๋า

---

# 16. 🕳️ กับดัก

มี 7 ช่อง

เมื่อผู้เล่นลงช่องกับดัก:

* สุ่มถอยหลัง 2–6 ช่อง
* แสดง Animation กับดัก
* ประกาศผล

ตัวอย่าง:

> ช่อง 41 เป็นกับดัก คุณถอยหลัง 4 ช่อง ไปอยู่ช่อง 37

หากมีเกราะ ผู้เล่นต้องได้รับตัวเลือกใช้เกราะก่อนผลเสียเกิดขึ้น

---

# 17. 🌊 กระแสน้ำ

มี 5 ช่อง

เมื่อผู้เล่นลงช่องกระแสน้ำ:

* สุ่มถูกพัดถอยหลัง 1–5 ช่อง
* แสดง Animation น้ำ
* สามารถมีเสียงน้ำ
* หากเหตุการณ์นี้ถูกกำหนดให้ป้องกันด้วยเกราะ ผู้เล่นสามารถเลือกใช้เกราะได้

ตัวอย่าง:

> ช่อง 53 มีกระแสน้ำ คุณถูกพัดถอยหลัง 3 ช่อง

---

# 18. 👻 ช่องผี

มี 5 ช่อง

ผีเป็นเหตุการณ์ด้านลบที่แตกต่างจากกับดักและกระแสน้ำ

ผลของผีควรเป็นเหตุการณ์ เช่น:

* เสียเทิร์นถัดไป
* หรือผลเสียที่ไม่ใช่การถอยหลัง

ข้อกำหนดของเกมฉบับนี้:

> ผีไม่ควรใช้เพื่อสร้างการเคลื่อนที่ถอยหลังโดยตรง เพราะหน้าที่นั้นเป็นของกับดักและกระแสน้ำ

อย่างน้อยหนึ่งผลของผีต้องสามารถป้องกันด้วยเกราะศักดิ์สิทธิ์ได้

หากเป็นผลเสียที่ป้องกันได้และมีเกราะ ให้ถามผู้เล่นก่อน

---

# 19. 🌀 วาร์ป

มี 4 ช่อง

เมื่อผู้เล่นลงวาร์ป:

วาร์ปจะสุ่มเป็นหนึ่งในสองประเภท:

### วาร์ปโชคดี

เดินหน้า 10–20 ช่อง

ตัวอย่าง:

> วาร์ปทำงาน! คุณโชคดี ได้เดินหน้า 15 ช่อง

### วาร์ปโชคร้าย

ถอยหลัง 10–20 ช่อง

ตัวอย่าง:

> วาร์ปทำงาน! คุณโชคร้าย ถูกส่งย้อนกลับ 12 ช่อง

หากเป็นวาร์ปโชคร้ายและมีเกราะ ผู้เล่นสามารถเลือกใช้เกราะเพื่อป้องกันผลเสียได้

หากป้องกันสำเร็จ:

* ใช้เกราะ 1 ชิ้น
* ไม่เกิดการถอยหลัง

หากไม่ใช้:

* เกิดผลตามปกติ

การเคลื่อนที่จากวาร์ปต้องไม่ทำให้ตัวละครออกนอกช่วง 1–80

---

# 20. 🔑 กุญแจ

มีกุญแจทั้งหมด 6 ช่อง

เมื่อผู้เล่นลงช่องกุญแจ:

> ได้รับกุญแจ 1 ดอก

กุญแจจะเก็บอยู่ใน Inventory ของผู้เล่น

ผู้เล่นไม่จำเป็นต้องใช้ทันที

สามารถเก็บไว้ใช้กับประตูภายหลังได้

ตัวอย่าง:

> คุณพบกุญแจ ได้รับกุญแจ 1 ดอก ตอนนี้มีกุญแจ 2 ดอก

---

# 21. 🚪 ประตู

มีประตู 6 ช่อง

ข้อกำหนด:

* ไม่มีประตูก่อนช่อง 10
* ประตูทุกบานต้องนำไปข้างหน้า
* ประตูแต่ละบานมีปลายทางที่สุ่ม
* ปลายทางต้องอยู่ข้างหน้าตำแหน่งประตู
* ประตูหนึ่งบานใช้กุญแจ 1 ดอก
* ผู้เล่นสามารถเก็บกุญแจไว้ก่อน

หากผู้เล่นมี Key:

> คุณพบประตู ต้องการใช้กุญแจเปิดประตูหรือไม่?

ให้เลือก:

* ใช้กุญแจ
* ไม่ใช้

หากใช้:

* กุญแจลดลง 1
* เปิดประตู
* ผู้เล่นเคลื่อนที่ไปยังปลายทาง
* แสดง Animation ประตู

หากไม่มี Key:

> คุณพบประตู แต่ไม่มีกุญแจ ประตูยังเปิดไม่ได้

ไม่มีการลงโทษ

---

# 22. คู่กุญแจกับประตู

กุญแจ 6 ดอกและประตู 6 บานให้สร้างเป็นคู่ในตอนสร้างเกม

ข้อกำหนด:

* กุญแจของคู่ต้องอยู่ก่อนประตู
* ระยะห่างอย่างน้อย 6 ช่อง

ตัวอย่างที่ถูกต้อง:

> กุญแจช่อง 14 → ประตูช่อง 23

เพราะห่าง 9 ช่อง

ตัวอย่างที่ไม่ถูกต้อง:

> กุญแจช่อง 18 → ประตูช่อง 21

เพราะห่างเพียง 3 ช่อง

ต้องตรวจสอบ Constraint ทุกครั้งที่สร้างกระดาน

---

# 23. การเกิด Special Chain

เพื่อป้องกันการเกิดเหตุการณ์ต่อเนื่องที่ซับซ้อนเกินไป:

**การเดินที่เกิดจาก Special Event จะไม่เรียก Special Event ของช่องปลายทางซ้ำทันที**

ตัวอย่าง:

ผู้เล่นลงช่อง 20 เป็น 🚀

แล้วถูกส่งไปช่อง 25

แม้ช่อง 25 จะเป็น 🕳️ ก็ไม่ให้กับดักทำงานต่อทันที

ระบบถือว่าการเคลื่อนที่จาก Special Event จบลงแล้ว

ช่อง 25 จะสามารถทำงานตามปกติหากผู้เล่นมาลงช่อง 25 จากการทอยลูกเต๋าในเทิร์นอื่น

กฎนี้มีไว้ป้องกัน:

* Infinite Chain
* Event ซ้อนกัน
* การคำนวณ State ซ้ำ
* Animation ซ้อนกัน
* ความสับสนของ Screen Reader

---

# 24. ผู้เล่นหลายคนอยู่ช่องเดียวกัน

สามารถมีผู้เล่นหลายคนอยู่ช่องเดียวกันได้

**ไม่มี Interaction ระหว่างตัวละคร**

ห้ามมี:

* การผลัก
* การชนแล้วเสียตำแหน่ง
* การโจมตี
* การแย่งช่อง
* การเสียเทิร์น
* Priority ตามลำดับการมาถึง

ผู้เล่นทุกคนอยู่ร่วมช่องได้อย่างอิสระ

หากมีหลายตัวละครในช่องเดียวกัน ให้จัดวางทางภาพ เช่น:

* 1 ตัว: กลาง
* 2 ตัว: ซ้าย / ขวา
* 3–4 ตัว: กลุ่มเล็ก
* 5–6 ตัว: กระจายภายในช่อง

ตัวละครต้องมีขนาดเล็กพอไม่บังเลขช่อง

ชื่อผู้เล่นควรอยู่เหนือหัวตัวละคร เช่น:

> น้องฟ้า
> 🐰

ชื่อควรมีขนาดเล็กและไม่บดบังตัวละครอื่นมากเกินไป

---

# 25. Player Status

ด้านบนของเกมควรมี Status Card ของผู้เล่นทุกคน

แต่ละ Card ควรแสดง:

* สัตว์
* ชื่อผู้เล่น
* ตำแหน่ง
* จำนวนกุญแจ
* จำนวนเกราะศักดิ์สิทธิ์
* สถานะเทิร์น

ตัวอย่าง:

> 🐰 น้องฟ้า
> ช่อง 32 จาก 80
> 🔑 2
> 🛡️ 1

ข้อมูลบน Card และตัวละครบนกระดานต้องมาจาก State ชุดเดียวกัน

ห้ามมี State คนละชุดจนเกิดกรณี:

> Card อยู่ช่อง 32 แต่ตัวละครอยู่ช่อง 31

# 26. Screen Reader

เกมต้องรองรับ:

* NVDA
* JAWS
* VoiceOver
* Keyboard
* Touch

ระบบ ARIA ควรแยก:

* polite announcement
* assertive announcement

และใช้ Queue เพื่อป้องกันข้อความชนกัน

ไม่ควรให้ Animation ทางภาพทำให้ Screen Reader อ่านข้อความซ้ำจำนวนมาก

---

# 27. ตัวอย่างการประกาศ

เมื่อทอย:

> คุณทอยได้ 5

เมื่อเดิน:

> คุณเดินจากช่อง 27 ไปช่อง 32

เมื่อพบสมบัติ:

> ช่อง 32 เป็นกล่องสมบัติ คุณได้รับเกราะศักดิ์สิทธิ์ 1 ชิ้น

เมื่อได้กุญแจ:

> คุณได้รับกุญแจ 1 ดอก ตอนนี้มีกุญแจ 2 ดอก

เมื่อเจอประตู:

> คุณพบประตู ต้องการใช้กุญแจเปิดประตูหรือไม่?

เมื่อชนะ:

> เกมจบแล้ว น้องฟ้าเป็นผู้ชนะ

---

# 28. การชนะ

ผู้เล่นคนแรกที่ **ลงช่อง 80 แบบตรงตำแหน่ง** เป็นผู้ชนะทันที

ตัวอย่าง:

79 + ลูกเต๋า 1

> ลงช่อง 80 → ชนะทันที

แต่:

78 + ลูกเต๋า 5

> เกิน 80 → Bounce Back → ไม่ชนะ

เมื่อชนะ:

1. หยุดการเล่น
2. หยุดการทอย
3. ประกาศผู้ชนะ
4. เล่นเสียงชนะ
5. แสดง Animation ฉลอง
6. แสดงหน้าสรุปผล
7. Synchronize สถานะจบเกมไปทุก Client

ไม่ต้องเล่นต่อจนทุกคนเดินครบ

---

# 29. หน้าสรุปผล

หน้าสรุปควรแสดง:

* ผู้ชนะ
* สัตว์ของผู้ชนะ
* ชื่อผู้ชนะ
* ตำแหน่ง 80
* สถานะผู้เล่นอื่น
* ปุ่มกลับชุมชน/ออกจากเกมตามระบบเดิม

ควรมี Visual Celebration

และ Screen Reader ต้องประกาศผลอย่างชัดเจน

---

# 30. หลักสำคัญของเกม

เกมนี้ต้องรักษาหลัก 5 ข้อ:

1. **สุ่มทุกเกม**
2. **Host เป็นผู้ตัดสิน State สำคัญ**
3. **ทุก Client เห็น Game State เดียวกัน**
4. **Animation และ Accessibility ต้องสอดคล้องกัน**
5. **เกมต้องเล่นได้จริงทั้งผู้ใช้ Screen Reader และผู้เล่นทั่วไป**

---

# 31. สิ่งที่ห้ามนำมาจากเกมต้นแบบ

แม้เกมจะนำโครงสร้างที่ดีจาก Snake และ Domino มาใช้ แต่ห้ามนำกติกาเหล่านี้เข้ามา:

* ระบบการ์ดของ Snake
* ระบบเลือกใช้การ์ด
* ระบบ Domino
* ระบบจั่วไพ่/โดมิโน
* คะแนนแบบ Domino
* กติกา Reverse ของ Domino
* กติกา Skip/Draw ของ Domino
* กติกาเฉพาะของ UNO
* กติกาเฉพาะของ Snake ที่ไม่เกี่ยวกับเกมกระดาน 80 ช่อง

ใช้เฉพาะ Architecture, Accessibility, Synchronization, Lobby, Networking, Animation และแนวคิด UI ที่เหมาะสมเท่านั้น

---

# 32. เป้าหมายสุดท้าย

เกมต้องให้ความรู้สึกเหมือน:

> “การผจญภัยบนกระดานที่ทุกเกมไม่เหมือนกัน”

ผู้เล่นรู้ว่า:

* ต้องทอยลูกเต๋า
* ต้องเดินไปข้างหน้า
* มีเหตุการณ์ระหว่างทาง
* มีของให้เก็บ
* มีประตูและกุญแจ
* มีความเสี่ยง
* มีโอกาสโชคดี
* และต้องไปให้ถึงช่อง 80 ก่อนคนอื่น

แต่ผู้เล่นไม่ควรรู้ล่วงหน้าว่า:

> ช่องไหนเป็นอะไรในเกมถัดไป

ดังนั้นการสุ่ม Layout และ Effect Configuration เป็นหัวใจสำคัญของเกม
